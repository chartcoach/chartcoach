---
title: Browser Loading API
description: Load ChartCoach catalog parquet artifacts in browser runtimes.
---

The browser entrypoint loads a published parquet catalog over HTTP. Pass a manifest when the caller needs section-role and label-family validation.

```ts
import { fetchCatalog } from "@chartcoach/catalog/browser";

const catalog = await fetchCatalog("/catalog.parquet", {
  manifest: "/MANIFEST.md",
});
```

## fetchCatalog

`fetchCatalog(catalogUrl, options?)`

Fetch `catalogUrl`, decode the parquet rows, validate each row, and return a `Catalog`.

```ts
const catalog = await fetchCatalog(
  "https://example.com/guidelines/catalog.parquet",
  {
    manifest: "https://example.com/guidelines/MANIFEST.md",
    request: {
      headers: {
        accept: "application/octet-stream",
      },
    },
  },
);
```

`options.manifest` accepts a parsed manifest, a URL string, or a `URL` object. When it is a URL, `fetchCatalog` retrieves the manifest with the same request options and validates catalog coverage.

`options.request` is passed to both fetch paths. Use it for headers, credentials, cache policy, or abort signals.

## Returned Catalog

`fetchCatalog` returns the same `Catalog` class exported from `@chartcoach/catalog`.

```ts
for (const guideline of catalog) {
  console.log(guideline.id, guideline.title, guideline.labels.length);
}
```

Each guideline is flat:

```ts
type Guideline = {
  id: string;
  title: string;
  bibliography?: string;
  description: string;
  labels: readonly string[];
  body: string;
  sections: readonly GuidelineSection[];
  references: readonly string[];
};
```

Malformed rows reject the load with `CatalogError`. Manifest validation also rejects undefined section roles and label families.

## Runtime Boundary

Use `@chartcoach/catalog/browser` for static sites and browser applications that load published catalog artifacts.

Use `@chartcoach/catalog/server` for local filesystem paths in scripts, build steps, and server applications.
