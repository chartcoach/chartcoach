---
title: Catalog Records
description: Source record shape shared by ChartCoach package APIs.
---

The public catalog record is `Guideline`. JavaScript and Python loaders return the same flat record fields for catalog entries, whether the source is an authored folder or a generated parquet artifact.

```ts
type Guideline = {
  id: string;
  title: string;
  bibliography?: string;
  description: string;
  labels: readonly string[];
  body: string;
  sections: readonly GuidelineSection[];
  references: readonly string[];
};
```

## Guideline

`id`

Stable guideline id.

`title`

Short action-oriented title.

`bibliography`

Optional bibliography filename from folder-authored catalogs.

`description`

One-sentence summary used by listing and retrieval surfaces.

`labels`

Controlled-vocabulary labels. The packages preserve these as strings. Label semantics live in the catalog data, not in loader-specific enums.

Labels must use `family:category` or `family:category:modifier`. The manifest must define every label family used by `catalog.parquet`.

`body`

Full markdown body.

`sections`

Role-tagged section records parsed from the body.

`references`

BibTeX entries associated with the guideline.

## GuidelineSection

```ts
type GuidelineSection = {
  role: string;
  title: string;
  content: string;
};
```

`role`

Section role such as `advice`, `reason`, `context`, `exceptions`, `check`, or `fix`.

Section roles are catalog-owned strings. The manifest must define every section role used by `catalog.parquet`.

`title`

Section heading.

`content`

Section markdown content.

## Validation

JavaScript loading validates rows at the storage boundary and returns flat `Guideline` records. Invalid rows fail before a `Catalog` is constructed.

Python loading validates the same source shape through `Catalog.from_parquet`, `Catalog.from_folder`, `CatalogEntry.from_mapping`, and `Guideline.from_mapping`.

Bundle loaders also validate `MANIFEST.md`. `Section Roles` and `Label Families` are required headings, and each role or family is a level-3 subheading under the matching required heading.

Do not rely on loaders to fill missing titles, descriptions, labels, sections, or references. The catalog row should already be complete.
