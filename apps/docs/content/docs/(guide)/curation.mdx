Catalog work moves through four visible states:

```text
guideline.md files
  -> MANIFEST.md + entries.parquet
  -> release.json + release files
  -> catalog.json selecting the public release
```

`catalog build` creates `entries.parquet` from the authored Markdown files.
`build_release` adds `release.json`, which records the byte count and SHA-256
hash of every release file. The final selection command copies that release
record to `catalog.json`.

## Install the curation tools

This guide assumes `uv`, Python 3.10 through 3.14, and a POSIX shell.

```bash
uv venv
source .venv/bin/activate
uv pip install \
  "chartcoach[curation,projection] @ https://files.peter.gy/packages/python/chartcoach/0.2.0/892f120cb377/chartcoach-0.2.0-py3-none-any.whl"
```

## Author a guideline

Create `authored-catalog/` with a manifest and one guideline entry:

```text
authored-catalog/
├── MANIFEST.md
└── entries/
    └── direct-labels/
        └── guideline.md
```

`MANIFEST.md` lists every section role and label family used by the
guidelines:

```md
# Sample Catalog

## Section Roles

### advice

Recommended actions the reader can apply.

## Label Families

### chart

Labels that identify the chart type, such as `chart:line`.
```

Write `entries/direct-labels/guideline.md`:

```md
---
id: direct-labels
title: Use direct labels
description: Label marks directly when space permits.
labels:
  - chart:line
---

## Advice <!-- role: advice -->

Place the label close to the mark it names.
```

A guideline can add `bibliography: references.bib` to its frontmatter. Place
that file beside `guideline.md` and cite a BibTeX key as `[@smith2024]` in a
section.

## Validate and build the catalog

Validate the authored files, write the two-file catalog, and read the result:

```bash
chartcoach catalog validate --source ./authored-catalog
chartcoach catalog build \
  --source ./authored-catalog \
  --out ./dist/catalog

chartcoach catalog describe --source ./dist/catalog
chartcoach catalog read --source ./dist/catalog direct-labels
```

`dist/catalog` must not exist before `catalog build` runs. A failed build
removes the partial directory. A successful build contains `MANIFEST.md` and
`entries.parquet`.

## Build a release

A release combines the catalog files with a `release.json` record. The digest
printed here identifies that exact set of files:

```python
from pathlib import Path

from chartcoach import open_catalog
from chartcoach.catalog.curation import build_release

release = build_release(
    open_catalog("dist/catalog"),
    Path("dist/release"),
)

print(release.digest)
```

`dist/release` must also be new. The directory now contains `MANIFEST.md`,
`entries.parquet`, and `release.json`.

### Add an index profile

Each index profile requires `profile.json` and `index.tar.gz`. The metadata
records the entries and manifest digests, persisted embedding binding, vector
dimensions, distance metric, Python requirements, LanceDB version, and
projection metadata. Profile IDs are lowercase single-component names such as
`minilm-normalized`. Building this example can download the embedding model
when it is not already cached.

```bash
uv pip install sentence-transformers==5.6.1
```

```python
from pathlib import Path

from lancedb.embeddings import get_registry

from chartcoach import open_catalog
from chartcoach.catalog.curation import EmbeddingProfile, build_release

embedding = get_registry().get("sentence-transformers").create(
    name="all-MiniLM-L6-v2",
    device="cpu",
    normalize=True,
    trust_remote_code=False,
)

release = build_release(
    open_catalog("dist/catalog"),
    Path("dist/release-indexed"),
    profiles={
        "minilm-normalized": EmbeddingProfile(
            embedding=embedding,
            distance_metric="cosine",
            python_requirements={"sentence-transformers": "5.6.1"},
            export_documents=True,
            umap={
                "n_neighbors": 15,
                "min_dist": 0.1,
                "metric": "cosine",
                "random_state": 42,
            },
        )
    },
)
```

This build writes `profile.json`, `index.tar.gz`, the requested portable
`documents.parquet` export, and `projection.parquet`. The document export holds
text, labels, hashes, and vectors. The projection export holds identity,
coordinates, and the original vector-space neighbor graph.

`export_documents=False`, the default, keeps the LanceDB table as the document
and vector representation. `umap=None`, the default, skips
[UMAP](https://umap-learn.readthedocs.io/) and omits `projection.parquet`. A
mapping, including `{}`, requests projection and requires
`chartcoach[projection]`. `EmbeddingProfile.distance_metric` controls index
retrieval distance. `umap["metric"]` controls the projection neighbor graph.
Every `python_requirements` value is an exact installed distribution version.
`build_release` rejects a missing or different producer version.

### Reuse an existing index profile

`ProfileReuse` copies a verified index archive and can derive a new projection
or portable document export from its stored vectors. It requires the same
entries and manifest digests, so embeddings are reused with the catalog that
owns them. `release` names an exact local release directory or its
`release.json` file.

```python
from chartcoach import open_catalog
from chartcoach.catalog.curation import ProfileReuse, build_release

release = build_release(
    open_catalog("dist/catalog"),
    "dist/release-reprojected",
    profiles={
        "minilm-reprojected": ProfileReuse(
            release="dist/release-indexed",
            profile="minilm-normalized",
            umap={"n_neighbors": 30, "random_state": 42},
        )
    },
)
```

The copied `index.tar.gz` retains its embedding binding and producer LanceDB
version. The new release digest covers the new profile ID and projection bytes.
This build reads stored vectors and does not construct the embedding provider.
Publication validation also checks the trusted alias registration and exact
provider versions listed by the reused profile.

## Publish the release

The publish and select commands below write to remote object storage. They are
intended for maintainers with store credentials, write permission, `jq`, and
a public HTTPS base URL for the same storage. Their dry runs and the validation
command do not write remote state.

Set those deployment-specific values first:

```bash
CATALOG_STORE="s3://your-bucket/chartcoach"
PUBLIC_BASE="https://catalog.example.com/chartcoach"
RELEASE_DIRECTORY="dist/release"
```

Set `RELEASE_DIRECTORY="dist/release-indexed"` when publishing the optional
indexed release built above.

Validate the release and capture its digest:

```bash
RELEASE_DIGEST="$(
  chartcoach catalog release validate "$RELEASE_DIRECTORY" --format json |
    jq -r '.digest'
)"
```

Preview the uploaded paths, then publish them:

```bash
chartcoach catalog release publish \
  "$RELEASE_DIRECTORY" \
  --store "$CATALOG_STORE" \
  --dry-run

chartcoach catalog release publish \
  "$RELEASE_DIRECTORY" \
  --store "$CATALOG_STORE"
```

Publication writes the release files under
`catalog/releases/$RELEASE_DIGEST/` and writes `release.json` last. Verify the
published catalog through its public URL:

```bash
RELEASE_URL="$PUBLIC_BASE/catalog/releases/$RELEASE_DIGEST/release.json"
chartcoach catalog describe --source "$RELEASE_URL"
```

The describe command verifies the byte count and SHA-256 hash of
`MANIFEST.md` and `entries.parquet` before reading them.

For an indexed release, inspect every profile and perform explicit FTS before
selection:

```bash
chartcoach catalog describe \
  --source "$RELEASE_URL" \
  --profile minilm-normalized
chartcoach catalog search \
  --source "$RELEASE_URL" \
  --profile minilm-normalized \
  --mode fts \
  "direct labels"
```

## Select the public release

Preview the change to `catalog.json`, then select the verified digest:

```bash
chartcoach catalog release select \
  "$RELEASE_DIGEST" \
  --store "$CATALOG_STORE" \
  --dry-run

chartcoach catalog release select \
  "$RELEASE_DIGEST" \
  --store "$CATALOG_STORE"
```

The final command reads the published `release.json`, verifies its digest, and
writes that record to `$PUBLIC_BASE/catalog.json`. Readers of that URL will see
the newly selected release. Python calls that omit `location` and commands that
omit `--source` read the official `files.peter.gy` catalog selection.
