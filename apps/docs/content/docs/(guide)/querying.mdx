chartcoach offers three ways to search a catalog:

| What you know                          | Command        |
| -------------------------------------- | -------------- |
| A label or phrase                      | `catalog list` |
| A relationship between tables          | `catalog sql`  |
| An idea, but not the catalog's wording | `catalog find` |

After choosing an ID, `catalog read` returns the full guideline and `catalog
cite` formats its sources.

Install the CLI and set the fixed three-record source used by the runnable
examples:

```bash
uv tool install \
  "chartcoach @ https://files.peter.gy/packages/python/chartcoach/0.2.0/892f120cb377/chartcoach-0.2.0-py3-none-any.whl"

CATALOG_SOURCE="https://files.peter.gy/packages/python/chartcoach/0.2.0/docs-catalog/c0f6dbec3dd31b07763b46fd458733db0b8b50c5793cf9447458119287129420/release.json"
```

## Match labels and words

This command requires the exact label `purpose:refine`, at least one label
that starts with `quality:`, and the substring `label` in the guideline ID,
title, or description:

```bash
chartcoach catalog list \
  --source "$CATALOG_SOURCE" \
  --label purpose:refine \
  --label-prefix quality: \
  --contains "label" \
  --limit 10 \
  --format json
```

The result includes this guideline ID and title:

```json
[
  {
    "id": "directly-label-series-instead-of-using-a-color-key",
    "title": "Directly label colored series instead of relying on a color key"
  }
]
```

Run `chartcoach catalog labels --source "$CATALOG_SOURCE"` before using an
exact label from an unfamiliar catalog.

## Join catalog tables

Inspect the available tables and columns before writing SQL:

```bash
chartcoach catalog schema --source "$CATALOG_SOURCE" --tables --row-counts
chartcoach catalog schema \
  --source "$CATALOG_SOURCE" \
  guidelines guideline_labels
```

The next query returns guidelines with both `purpose:refine` and any label in
the `quality` family:

```bash
chartcoach catalog sql "
  select distinct g.id, g.title
  from guidelines g
  join guideline_labels purpose
    on purpose.guideline_id = g.id
  join guideline_labels quality
    on quality.guideline_id = g.id
  where purpose.label = 'purpose:refine'
    and quality.family = 'quality'
  order by g.id
  limit 20
" --source "$CATALOG_SOURCE" --format json
```

The JSON object contains `columns`, `rows`, `row_count`, `truncated`, the
applied `limit`, and catalog digests. This query returns two rows. The CLI caps
SQL results at 100 rows by default. Pass `--limit` to set another cap.

## Search within guideline sections

`catalog find` searches an index stored with a catalog release. A profile is
the name of that index. A filter such as `role = 'section.mistakes'` restricts
matches to the `mistakes` section of each guideline.

The following template requires a release that publishes the named profile.
Replace `<digest>` and the profile name with values from that release. The
three-record demo release used earlier has no search index.

```bash
PROFILE_RELEASE_URL="https://catalog.example.com/catalog/releases/<digest>/release.json"

uvx --from \
  "chartcoach[index] @ https://files.peter.gy/packages/python/chartcoach/0.2.0/892f120cb377/chartcoach-0.2.0-py3-none-any.whl" \
  chartcoach catalog find \
  --source "$PROFILE_RELEASE_URL" \
  --profile sentence-transformers/all-MiniLM-L6-v2 \
  --mode fts \
  --where "role = 'section.mistakes'" \
  --limit 5 \
  --format json \
  "legend makes the lines hard to identify"
```

Full-text search (`fts`) needs the query string alone. Vector and hybrid
search also need a vector created with the profile's embedding model.

## Read and cite the selected guideline

Candidate results contain summaries. Read the selected guideline before
applying its recommendation, then format its link and source citations. The ID
below comes from the runnable `catalog list` example. Read an indexed-search
result from the same release that produced it.

```bash
GUIDELINE_ID="directly-label-series-instead-of-using-a-color-key"

chartcoach catalog read "$GUIDELINE_ID" \
  --source "$CATALOG_SOURCE" \
  --source-detail full \
  --format markdown

chartcoach catalog cite "$GUIDELINE_ID" \
  --source "$CATALOG_SOURCE" \
  --format markdown
```

The `read` output contains every section in the selected record, followed by
its source list. The `cite` output contains the public guideline URL and
formatted source citations.
