Start with what you know about the chart:

| What you know                                       | Use                                    |
| --------------------------------------------------- | -------------------------------------- |
| An exact label, term, or short phrase               | `catalog list`                         |
| A relationship between labels, sections, or sources | `catalog sql`                          |
| A topic to search within guideline text             | `catalog search` with an index profile |

Install the CLI with [uv](https://docs.astral.sh/uv/):

```bash
uv tool install chartcoach
```

Commands use the public catalog by default. For another catalog, set
`CHARTCOACH_SOURCE` to its descriptor location or pass `--source`. Use an exact
release when a sequence of commands must keep the same catalog contents.

## Filter candidates

Find recommendations about labels that also address quality:

```bash
chartcoach catalog list \
  --label purpose:refine \
  --label-prefix quality: \
  --contains label \
  --limit 10 \
  --format table
```

Every filter must match. `--contains` matches one contiguous substring in the
ID, title, or description. Matching ignores case and treats whitespace,
hyphens, and underscores as equivalent separators. Search `labels` and
`overlap` separately when those concepts need not appear together.

The result includes candidate IDs, which you pass to `read` and `cite`.
Inspect `catalog labels` before using unfamiliar exact labels.

In Python, use `catalog.query(labels=[...], contains="label", limit=10)`.
In JavaScript, use `catalog.query({ labels: [...], contains: "label", limit: 10 })`.

If nothing matches, shorten the phrase or relax exact filters. Section text
can match even when the entry's title and description do not. Search it with
SQL, or use full-text search when the release has an index profile. An empty
query result alone does not establish that the catalog has no relevant guidance.

## Query section text and relationships with SQL

Inspect the tables and columns before writing a query:

```bash
chartcoach catalog schema guidelines sections
```

Find a term in section text, including catalogs with no index profile:

```bash
chartcoach catalog sql "
  select distinct g.id, g.title
  from guidelines g
  join sections s on s.guideline_id = g.id
  where s.content ilike '%label%'
  order by g.id
" --limit 10 --format table
```

Use [native DuckDB in Python](/python#compose-duckdb-queries) for application
queries, parameters, and exports. The CLI accepts one read-only `SELECT` and
bounds its output.

## Search guideline text

An index profile contains searchable documents and their embedding binding.
Set `CATALOG_SOURCE` to a release with profiles, run `catalog describe` for
their names, and set `PROFILE` to the one you want:

```bash
uvx --from "chartcoach[index]" chartcoach catalog describe --source "$CATALOG_SOURCE"

uvx --from "chartcoach[index]" chartcoach catalog search \
  --source "$CATALOG_SOURCE" \
  --profile "$PROFILE" \
  --mode fts \
  --limit 5 \
  "direct labels"
```

Full-text search (`fts`) uses the stored text index and keeps embedding
providers idle. Use it for several concepts such as `labels overlap`.
`vector` and `hybrid` embed the query through the profile's LanceDB binding.
Install its reported
`python_requirements` and supply any required credentials before using those
modes. See [CLI search](/cli#search-an-index) for configuration.

To search a specific section, add `--where "role = 'section.advice'"`.
Python applications can use [the native LanceDB table](/python#search-and-read-matching-guidelines)
for filtering, reranking, and batch queries.

The limit counts search documents before deduplication into guideline matches.
Compare `documents_considered`, `match_count`, and `documents_truncated` when
checking coverage. An additional `--where "role = 'overview'"` search can
broaden candidates when many hits share a parent. Read complete entries to
recover their section context and exceptions.

`score_kind` is `distance` for vector search, where lower values rank first,
and `relevance` for full-text and hybrid search, where higher values rank first.
Scores describe retrieval within that query, mode, and profile. They do not
measure whether a recommendation applies to the user's chart.

## Read and cite selected guidance

Pass selected IDs together to read and cite. For example:

```bash
GUIDELINE_ID="directly-label-series-instead-of-using-a-color-key"
RELATED_ID="place-labels-and-annotations-next-to-marks"
chartcoach catalog read "$GUIDELINE_ID" "$RELATED_ID" --format markdown
chartcoach catalog cite "$GUIDELINE_ID" "$RELATED_ID" --format markdown
```

Read the advice, applicable situations, and exceptions before applying it.
`cite` returns the guideline link and formatted source citations. When a search
used a custom catalog, pass that same `--source` to both commands.

Inspect the publication before attributing a specific claim to it. A returned
citation identifies an attached source, while the record's context and the
chart evidence determine whether its guidance fits the task.
