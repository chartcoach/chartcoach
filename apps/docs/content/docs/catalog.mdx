The Guideline Catalog is the versioned collection of source-traced guideline
records. Each record keeps its retrieval labels, ordered prose sections, and
source references together.

```json
{
  "id": "directly-label-series-instead-of-using-a-color-key",
  "title": "Directly label colored series",
  "description": "Attach series identity to the marks that readers inspect.",
  "labels": ["chart:line:use", "operator:lookup"],
  "sections": [
    {
      "role": "advice",
      "title": "Move labels onto the marks",
      "content": "Place each series name next to its line or area."
    }
  ],
  "references": ["@misc{muth_colorblindness_2020, ...}"]
}
```

The Markdown body is derived from the ordered `sections`. Reference ids in the
section text resolve against the record's BibTeX strings.

## Storage forms

| Form              | Contains                                              | Use it for               |
| ----------------- | ----------------------------------------------------- | ------------------------ |
| Authored folder   | `MANIFEST.md` and `entries/<id>/guideline.md`         | Review and curation      |
| Compiled bundle   | `MANIFEST.md` and `entries.parquet`                   | Local readers and builds |
| Immutable release | `release.json`, core artifacts, and optional profiles | Verified distribution    |

`MANIFEST.md` defines every section role and label family used by its records.
Readers validate that vocabulary when they open a catalog.

## Release envelope

A schema 1 release uses artifact paths as keys:

```ts
type CatalogRelease = {
  schema_version: 1;
  digest: string;
  artifacts: Record<
    string,
    {
      sha256: string;
      bytes: number;
    }
  >;
};
```

`MANIFEST.md` and `entries.parquet` are required. The digest covers the schema
version and canonical artifact map. Readers verify the digest, byte count, and
SHA-256 value before decoding each artifact.

A release can add one artifact pair per embedding profile:

```text
release/
├── release.json
├── MANIFEST.md
├── entries.parquet
└── profiles/
    └── sentence-transformers/all-MiniLM-L6-v2/
        ├── documents.parquet
        └── index.tar.gz
```

Each `documents.parquet` row contains `id`, `parent_id`, `role`, `labels`,
`content_hash`, `text`, the embedding vector, projection coordinates, and
nearest neighbors. The matching archive contains one LanceDB table named
`documents`.

## Selection and immutability

`catalog.json` contains the release selected for public access. It is the
mutable entry document. The directory under
`catalog/releases/<digest>/` remains immutable.

Opening `catalog.json` refreshes the selection before reusing cached immutable
artifacts. Opening an exact `release.json` keeps one digest across runs.

## Query tables

Readers derive six relational tables from the compiled rows:

```text
guidelines
sections
guideline_labels
references
guideline_references
guideline_sources
```

Run `chartcoach catalog schema --tables --row-counts` against the selected
source before writing a query. Use [Querying](/querying) for complete
filter, SQL, and indexed-search examples.
