---
title: Catalog Structure
description: What a ChartCoach catalog bundle contains.
---

A ChartCoach catalog source contains `MANIFEST.md` beside authored guideline folders under `entries/`. A published release stores physical artifacts under `catalog/releases/<version>/<digest>/`: `metadata.json`, `MANIFEST.md`, `entries.parquet`, and derived artifacts such as LanceDB indexes.

```text
chartcoach/catalog
  MANIFEST.md
  entries/
    <guideline-id>/
      guideline.md
      references.bib
```

The artifact root exposes `https://artifacts.chartcoach.dev/index.json` as the release index. Package defaults read a pinned release metadata file under `catalog/releases/<version>/<digest>/`, then fetch the manifest and entries artifacts from that release directory.

## Guideline Records

Each record contains:

- `id`, `title`, and `description` for the recommendation.
- `labels` for catalog-owned metadata.
- `sections` for role-annotated guidance.
- `references` for BibTeX source entries.

## Manifest

`MANIFEST.md` must define `Section Roles` and `Label Families`. Each section role and label family is a level-3 subheading under the matching heading. Loaders validate that the manifest covers roles and label families used by `entries.parquet`.

## Bundle Directory

Use a bundle directory or metadata URL when callers need manifest validation. Use a direct parquet file only for table workflows that already know the catalog vocabulary.
