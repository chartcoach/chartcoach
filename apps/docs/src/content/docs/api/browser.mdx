---
title: Browser Loading API
description: Load ChartCoach entries parquet files in browser runtimes.
---

The browser entrypoint loads a published parquet catalog over HTTP. Resolve release metadata first, then pass the entries artifact URL with the manifest artifact URL.

```ts
import { artifact, artifactUrl, fetchCatalogRelease } from "@chartcoach/catalog";
import { fetchCatalog } from "@chartcoach/catalog/browser";

const release = await fetchCatalogRelease();
const entries = artifactUrl(release.metadataUrl, artifact(release.metadata, "entries"));
const manifest = artifactUrl(release.metadataUrl, artifact(release.metadata, "manifest"));

const catalog = await fetchCatalog(entries, { manifest });
```

## fetchCatalog

`fetchCatalog(catalogUrl, options?)`

Fetch `catalogUrl`, decode parquet rows, validate each row, and return a `Catalog`.

```ts
const release = await fetchCatalogRelease();
const entries = artifactUrl(release.metadataUrl, artifact(release.metadata, "entries"));
const manifest = artifactUrl(release.metadataUrl, artifact(release.metadata, "manifest"));

const catalog = await fetchCatalog(
  entries,
  {
    manifest,
    request: {
      headers: {
        accept: "application/octet-stream",
      },
    },
  },
);
```

`options.manifest` accepts a parsed manifest, URL string, or `URL` object. `options.request` is passed to both fetch paths.

## Runtime Boundary

Use `@chartcoach/catalog/browser` for static sites and browser applications. Use `@chartcoach/catalog/server` for local filesystem paths in scripts, build steps, and server applications.
