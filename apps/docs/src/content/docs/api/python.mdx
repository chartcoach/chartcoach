---
title: Python Catalog API
description: Load ChartCoach catalogs, inspect Polars tables, and query native DuckDB or LanceDB resources from Python.
---

The `chartcoach` package loads a catalog and returns native Python data tools at each boundary.

```python
from chartcoach import Catalog

catalog = Catalog.open()
catalog.guidelines().select("id", "title", "description")
```

## Load

`Catalog.open(path=None)`

Load the package-pinned default catalog when `path` is omitted. The default reads release metadata under `https://artifacts.chartcoach.dev/catalog/releases/<version>/<digest>/metadata.json`, downloads the manifest and entries artifacts once into the user's platform cache directory, and validates the package-pinned digest.

When `path` is provided, load an authored guideline folder, catalog bundle, metadata URL, or parquet file. A bundle contains `MANIFEST.md`, `entries.parquet`, and `metadata.json`. Release metadata may also describe heavier derived artifacts such as LanceDB index archives.

`Catalog.from_bundle(path)`

Load a bundle and validate section roles and label families against `MANIFEST.md`.

`Catalog.from_parquet(path)`

Load a serialized entries parquet file without manifest validation.

`Catalog.from_folder(folder_path)`

Load an authored folder where `MANIFEST.md` sits beside `entries/`.

`Catalog.from_entries(entries)`

Build a catalog from `Guideline` objects or flat guideline mappings.

`Guideline(...)`

Construct a guideline with either `body` or `sections`. When only `body` is provided, the body must parse into section records. When only `sections` is provided, the markdown body is built from those sections. Serialized guideline records always contain both fields.

## Tables

`catalog.guidelines()`

Return one row per guideline.

`catalog.sections()`

Return one row per guideline section.

`catalog.labels()`

Return distinct label segments used across the catalog.

`catalog.references()`

Return parsed BibTeX reference records.

`catalog.table(name)`

Return a named derived table.

## DuckDB

```python
conn = catalog.duckdb()
try:
    rows = conn.sql("select id, title from guidelines limit 5").pl()
finally:
    conn.close()
```

Use DuckDB when callers need joins over guidelines, sections, labels, and references. `chartcoach.duckdb.register_catalog(conn, catalog)` registers the same tables in a caller-owned DuckDB connection.

## LanceDB

```python
from chartcoach.search import index, search

table = index(catalog, "scratch/chartcoach-index")

docs = (
    table.search("overplotted scatter plots", query_type="fts", fts_columns="text")
    .where("role = 'overview'")
    .limit(3)
    .to_list()
)

hits = search(catalog, table, "overplotted scatter plots").to_dict()["rows"]
```

`index(catalog, uri)` creates or replaces a LanceDB table named `catalog_documents` and returns the native LanceDB `Table`. The table contains `id`, `parent_id`, `role`, `labels`, `content_hash`, and `text`.

Pass `embedding=...` to let LanceDB populate a `vector` column from `text` through a caller-provided LanceDB embedding function:

```python
from chartcoach.search import index

table = index(
    catalog,
    "scratch/chartcoach-index",
    embedding=embedding_function,
)
```

`open(uri, table_name="catalog_documents")` opens an existing LanceDB table. `chartcoach.search.lance.documents(catalog)` returns the Polars dataframe used to create a caller-owned LanceDB table. `model(embedding)` returns the LanceDB model used when the table should store embedding metadata.

`query(table, query, limit=10, where=None, mode="auto")` returns bounded raw document rows for CLI and MCP transports. Python callers can use `table.search(...)` directly when they need the full LanceDB query builder.
