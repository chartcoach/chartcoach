## Put the takeaway in the title and the technical definition in the description or notes <!-- role: advice -->

Use conversational, memorable wording in the most prominent text (often the title), then provide precise definitions and constraints in the description or notes. Avoid leading with technical terms when the audience is mainstream.

## Prominent text is for the message, not the metadata <!-- role: reason -->

Readers remember high-level statements more than detailed definitions; front-loading precision can distract from the intended message and reduce engagement. Separating the takeaway from the detailed definition preserves both accessibility and accuracy.

**Mechanism:** A two-layer text structure supports quick comprehension first and precise interpretation second.

**Evidence:** Using colloquial wording in prominent text and placing precise explanations later helps prevent precision from distracting from the main message [@muth_text_in_data_visualizations_2022].

**Notes:** Precision is not removed; it is repositioned to a less prominent element.

## Apply when communicating to general audiences <!-- role: context -->

- **User Goal:** Understand the headline insight quickly, then verify details if needed.
- **Task:** Rapid orientation and takeaway extraction.
- **Data:** Any; especially where definitions are nuanced (time windows, inclusion criteria).
- **Chart Setting:** Editorial charts and explanatory visuals with titles, descriptions, and notes.
- **Audience:** Mainstream or mixed audiences; skimmers.
- **Success Criterion:** The main point is memorable, and details remain available.

## When to lead with precision <!-- role: exceptions -->

**Break it when:** The precise definition fundamentally changes the interpretation and must be understood before any takeaway (for example, a narrow subset that could be mistaken for the whole). **Why:** A conversational headline could mislead if readers miss the constraint.

## Trade immediate precision for engagement <!-- role: costs -->

**Sacrifice:** The title may be less technically complete. **Risk:** Some readers may only read the headline and miss important caveats. **Mitigation:** Keep a short, visible description line that signals the key constraint.

## Common failure modes <!-- role: mistakes -->

**Mistake:** Packing the title with full technical definitions and jargon. **Why it fails:** It distracts from the message and increases cognitive load at first glance.

## Quick checks <!-- role: check -->

**Failure Sign:** The title reads like a methods note. **Quick Check:** If the title contains multiple clauses defining scope, move that material into the description/notes. **Stronger Test:** Ask readers what they remember after a brief view; if they recall none of the takeaway, the title is too technical.

## Fixes <!-- role: fix -->

- Rewrite the title as a plain-language statement of the takeaway.
- Put time windows, definitions, and inclusion criteria in the description or note.
- Keep the description visually de-emphasized but readable.
- Add a short annotation to clarify a crucial constraint near the relevant marks.
