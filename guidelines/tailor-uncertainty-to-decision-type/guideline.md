## The Rule <!-- role: advice -->

Classify the audience’s decision as (1) action threshold, (2) fixed options, or (3) option creation, and present only the uncertainties that matter for that decision class.

## The Logic <!-- role: reason -->

Different decisions require different uncertainty information: threshold choices hinge on both discrimination ability and decision rule; fixed-option choices hinge on sensitivity to uncertain parameters; option creation hinges on understanding causal structure and what science omits. Using the wrong uncertainty framing either overwhelms or leaves out decision-relevant unknowns [@fischhoffCommunicatingScientificUncertainty2014].

## Where to Apply <!-- role: context -->

- **User Goal:** Knowing whether to act now; choosing the best among alternatives; inventing or redesigning policy/response options.
- **Data Type:** Forecast categories (yes/no), numerical predictions with error, or causal/process models.
- **Audience:** Decision makers relying on scientific results (public, clinicians, officials, investors).

## When to Break It <!-- role: exceptions -->

- **Scenario:** A single communication must serve multiple decision types simultaneously.
- **Reason:** One audience segment may need a threshold signal while another needs parameter uncertainty for planning; you may need separate layers or products rather than a single framing [@fischhoffCommunicatingScientificUncertainty2014].

## The Price <!-- role: costs -->

- **The Sacrifice:** Extra upfront work to learn the decision context before designing the message.
- **The Risk:** Over-segmentation can fragment communications across audiences [@fischhoffCommunicatingScientificUncertainty2014].

## Common Mistakes <!-- role: mistakes -->

- **The Wrong Fix:** Using one generic uncertainty format for all contexts (e.g., always giving a single probability).
- **Why it fails:** It may omit value tradeoffs for thresholds, omit sensitivity for fixed options, or omit model structure for option creation [@fischhoffCommunicatingScientificUncertainty2014].

## How to Check <!-- role: check -->

- **Visual Sign:** Users ask “So what should I do?” when you intended to inform, or they ignore the message because it feels irrelevant.
- **The Test:** Ask a representative user to state their decision and what uncertainty they need; if they cannot map your message to a choice, the framing is mismatched [@fischhoffCommunicatingScientificUncertainty2014].

## How to Fix <!-- role: fix -->

- **Quick Fix:** Add a one-sentence “decision this supports” label and remove uncertainty details not needed for that decision class.
- **Best Fix:** Create separate message variants (threshold vs comparison vs causal understanding), each with its own uncertainty summary [@fischhoffCommunicatingScientificUncertainty2014].
