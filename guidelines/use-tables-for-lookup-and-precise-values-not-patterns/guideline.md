## The Rule <!-- role: advice -->

Use a table when readers need to look up specific items or act on precise numbers; use a chart when you need to communicate patterns, outliers, or an overall picture.

## The Logic <!-- role: reason -->

Tables support targeted retrieval of exact values (people scan for “their” row/column), while charts make global structure and extremes hard to miss. This distinction is the core decision criterion described in [@muth_tables_2019].

- **The Principle:** Match format to user task (lookup/precision vs. overview/pattern detection)
- **The Evidence:** [@muth_tables_2019]

## Where to Apply <!-- role: context -->

- **User Goal:** Finding a specific value (e.g., “my city,” “my age group”), making decisions from exact numbers, checking ranks, or comparing in two directions
- **Data Type:** Structured text + numbers; ranked lists; matrices where readers may compare across rows and columns
- **Audience:** Broad audiences in a storytelling context who won’t read a whole long table end-to-end [@muth_tables_2019]

## When to Break It <!-- role: exceptions -->

- **Scenario:** You need readers to quickly see trends, outliers, biggest/smallest values, or the “shape” of the data
- **Reason:** Tables are read sequentially and make it easier to miss patterns that charts reveal at a glance [@muth_tables_2019]

## The Price <!-- role: costs -->

- **The Sacrifice:** Less immediate visual overview than a chart; more cognitive effort to compare values mentally
- **The Risk:** Readers may stop before reaching key rows in long tables and miss important values [@muth_tables_2019]

## Common Mistakes <!-- role: mistakes -->

- **The Wrong Fix:** Using a table to “show the story” when the goal is pattern recognition
- **Why it fails:** Readers must compute comparisons in their heads and are more likely to miss trends/outliers than with a chart [@muth_tables_2019]

## How to Check <!-- role: check -->

- **Visual Sign:** The key message requires readers to scan many rows/columns and mentally calculate differences to notice it
- **The Test:** Ask: “Is the main takeaway a pattern/outlier/overall comparison?” If yes, the table is the wrong primary format [@muth_tables_2019]

## How to Fix <!-- role: fix -->

- **Quick Fix:** Reframe the table around lookup (e.g., enable readers to find “their” row) and keep only the most decision-critical precise numbers [@muth_tables_2019]
- **Best Fix:** Switch to a chart for the main takeaway and keep the table as a supporting lookup/precision component [@muth_tables_2019]
