## Use the title to say the point out loud <!-- role: advice -->

Write the title as the explicit question the table answers (or the claim it supports), using the same terms readers will scan for in the cells. Make the purpose unmistakable before the reader starts parsing columns.

## A question-title sets the reading strategy for a table <!-- role: reason -->

Without a strong title, readers approach tables like spreadsheets: they hunt for meaning row-by-row and column-by-column. An explicit question-title tells them what comparison to make and which information is supporting context versus the main result.

**Mechanism:** A clear title primes the reader’s task (e.g., ranking host cities by games) and reduces uncertainty about what the table is “for.”

**Evidence:** Making the goal non-secret by stating it clearly in the title is presented as a central step in turning a boring spreadsheet-like table into a communicative visualization [@mintzer_compact_tables_2024].

**Notes:** A question-title pairs well with a summary column that directly answers it.

## When readers might not know what to look for <!-- role: context -->

- **User Goal:** Understand what the table is trying to show, then extract the key answer.
- **Task:** Orient, then compare and rank.
- **Data:** Multiple columns of details that could support several stories.
- **Chart Setting:** Standalone table embedded in an article or report, often skimmed.
- **Audience:** Mixed familiarity; readers who scan headings before committing attention.
- **Success Criterion:** Readers can state what the table answers after reading only the title.

## When the surrounding text already frames the question tightly <!-- role: exceptions -->

**Break it when:** The table is immediately preceded by a specific prompt or headline that already states the exact question. **Why:** Repeating the same wording can waste space and reduce scannability.

## Costs of explicit question-titles <!-- role: costs -->

**Sacrifice:** Less room for nuance or secondary context in the title. **Risk:** Overpromising certainty if the table only partially answers the question. **Mitigation:** Add a brief subtitle for scope (time period, source, or definition) while keeping the main title task-focused.

## Common title failures <!-- role: mistakes -->

- **Mistake:** Using a generic title like “EURO 2024 host cities and their games.” **Why it fails:** It describes contents but does not guide the reader to the intended comparison.
- **Mistake:** Burying the question in body text instead of the title. **Why it fails:** Many readers will skim the table without reading surrounding paragraphs.

## Quick checks for title clarity <!-- role: check -->

**Failure Sign:** Two readers give different answers about what the table is “about.” **Quick Check:** Ask someone to read only the title and predict what the first column should contain; they should be close. **Stronger Test:** Remove the table and show only the title; readers should still understand the intended takeaway.

## If a question-title still feels too long <!-- role: fix -->

- Convert the question into a short claim (e.g., “Berlin, Dortmund, and München hosted the most games”) and keep definitions in a subtitle.
- Add a lead-in label above the table (e.g., “Key question: …”) and keep the title compact.
- Split the table into a ranked summary view and a details view, each with its own focused title.
- If the story is about change over time, move the time framing into the title and keep the comparison term consistent in the cells.
