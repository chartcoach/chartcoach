## Define visualization literacy as reading and interpreting visually represented data <!-- role: advice -->

Define visualization literacy as the ability and skill to read and interpret visually represented data and to extract information from data visualizations.

## Why a consumption-focused definition stabilizes measurement scope <!-- role: reason -->

A concrete, consumption-focused definition constrains what the instrument (or evaluation) should include: tasks that involve reading and interpreting what is already encoded in the visualization, rather than producing new representations or performing tool-manipulation skills. This reduces construct drift and helps ensure that tasks and items align to the intended skill.

**Mechanism:** A narrower construct definition reduces ambiguity in what counts as evidence of the skill, which improves alignment between tasks, items, and score interpretation.

**Evidence:** A definition centered on reading and interpreting visually represented data was used to guide blueprinting and item generation for a visualization literacy assessment, explicitly excluding “produce” tasks (e.g., sorting/deriving) from the measured construct [@leeVLATDevelopmentVisualization2017].

**Notes:** This definition targets non-expert consumers of visualizations rather than expert visualization designers.

## When you are scoping a visualization literacy measure or evaluation <!-- role: context -->

- **User Goal:** Establish what “visualization literacy” means before designing training, tests, or evaluation criteria.
- **Task:** Specify inclusion/exclusion boundaries for what performance will count toward literacy.
- **Data:** Any dataset type that will be encountered via standard charts.
- **Chart Setting:** Instrument design, curriculum design, or study design.
- **Audience:** Non-expert users (e.g., adults who learned common charts in K–12).
- **Success Criterion:** A definition that reliably guides task selection and item writing.

## When not to use this definition as-is <!-- role: exceptions -->

**Break it when:** You are measuring visualization production skill (e.g., choosing encodings, authoring charts, interacting to transform views). **Why:** The definition intentionally excludes “produce/manipulate” tasks, so it will under-measure those abilities.

## Tradeoffs of a consumption-only definition <!-- role: costs -->

**Sacrifice:** You do not capture chart authoring, interaction proficiency, or higher-level analytic planning. **Risk:** Stakeholders may overgeneralize scores to “data analysis ability” broadly. **Mitigation:** Explicitly label the construct as reading/interpretation literacy when reporting results.

## Common ways this goes wrong in practice <!-- role: mistakes -->

**Mistake:** Treating visualization literacy scores as equivalent to end-to-end analytic competence. **Why it fails:** The construct does not include planning analytic sequences, tool fluency, or insight generation beyond the encoded view.

## Quick checks that your definition is being applied correctly <!-- role: check -->

**Failure Sign:** Items or evaluations reward people for using interface features or computing derived values not directly encoded. **Quick Check:** For each task, ask whether it can be answered by reading the given visual encoding without transforming the display. **Stronger Test:** Map each item to a task taxonomy category and verify it is “read/interpret,” not “produce/manipulate.”

## What to do instead when you need broader ability coverage <!-- role: fix -->

- Add a separate construct and subtest for visualization production (encoding choice, redesign, communication).
- Add a separate construct and subtest for interaction/tool proficiency if interactive techniques are central to the environment.
- Add a separate construct and subtest for analytic workflow skills (goal formation, task sequencing, insight reporting).
- Report these constructs as distinct scores rather than folding them into a single “literacy” score.
