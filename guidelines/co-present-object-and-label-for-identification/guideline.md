## The Rule <!-- role: advice -->

Show an object and its label together (and keep them concurrently visible) when you need the viewer to identify the object correctly.

## The Logic <!-- role: reason -->

When labels and objects co-appeared, viewers shifted fixations between them, suggesting integration of label and object information (e.g., pyrimidine dimer and its label; photolyase and its label) [@faradayDesigningEffectiveMultimedia1997].

- **The Principle:** Integration through alternating fixations
- **The Evidence:** [@faradayDesigningEffectiveMultimedia1997]

## Where to Apply <!-- role: context -->

- **User Goal:** Learn terminology; map names to visual structures.
- **Data Type:** Labeled diagrams/animations with multiple entities.
- **Audience:** Novices; also useful whenever terms are unfamiliar.

## When to Break It <!-- role: exceptions -->

- **Scenario:** The label is already known and the goal is pure motion understanding.
- **Reason:** The label may be redundant and add clutter.

## The Price <!-- role: costs -->

- **The Sacrifice:** More on-screen text; potential clutter.
- **The Risk:** Over-labeling can compete with the main visual message.

## Common Mistakes <!-- role: mistakes -->

- **The Wrong Fix:** Introducing a label well before/after the object appears.
- **Why it fails:** The viewer cannot easily bind the term to the object without coordinated attention shifts [@faradayDesigningEffectiveMultimedia1997].

## How to Check <!-- role: check -->

- **Visual Sign:** Users describe “a thing” but can’t name it, or misname it.
- **The Test:** Ask users to point to the labeled object while saying its name; confusion indicates poor co-presentation.

## How to Fix <!-- role: fix -->

- **Quick Fix:** Delay the label until the object appears (or vice versa) so they overlap in time.
- **Best Fix:** Place the label near the object and reveal both together with a stable period for reading and visual confirmation [@faradayDesigningEffectiveMultimedia1997].
