## Cover eight core visualization reading tasks when assessing visualization literacy <!-- role: advice -->

Ensure your assessment includes items for these tasks: Retrieve Value, Find Extremum, Determine Range, Characterize Distribution, Find Anomalies, Find Clusters, Find Correlations/Trends, and Make Comparisons.

## Why task breadth improves construct representation <!-- role: reason -->

Visualization literacy is not a single operation; it is reflected in multiple recurring reading and interpretation tasks. Covering a broader set of tasks reduces the risk that the test measures only elementary lookup or only trend inference, and it helps separate strengths and weaknesses by task type.

**Mechanism:** Diverse task sampling reduces construct underrepresentation by requiring multiple kinds of visual decoding and comparison operations.

**Evidence:** A visualization literacy assessment blueprint combined visualization task taxonomies into eight reading/interpretation tasks and used them to generate and evaluate items across 12 visualization types [@leeVLATDevelopmentVisualization2017].

**Notes:** Additional underlying tasks may be needed for certain charts (e.g., binning or hierarchy identification).

## When to apply this task set <!-- role: context -->

- **User Goal:** Measure or teach general visualization literacy for non-experts.
- **Task:** Build an item pool or exercise bank spanning multiple cognitive demands.
- **Data:** Mixed: univariate distributions, bivariate/multivariate tables, temporal series, geographic rates, hierarchies.
- **Chart Setting:** Static charts or minimally interactive settings.
- **Audience:** Non-expert adults; mixed statistical background.
- **Success Criterion:** Scores reflect multiple reading competencies rather than one narrow skill.

## When this task set is insufficient <!-- role: exceptions -->

**Break it when:** The target construct includes interactive operations (filtering, sorting, brushing) as part of literacy. **Why:** The task set is focused on reading/interpreting given encodings rather than producing/transforming views.

## Tradeoffs of broad task coverage <!-- role: costs -->

**Sacrifice:** More items are needed to represent each task adequately, increasing test length. **Risk:** Some tasks may be weakly represented for certain chart types, reducing diagnostic power. **Mitigation:** Use a blueprint to balance tasks and track per-task reliability where possible.

## Common task coverage mistakes <!-- role: mistakes -->

**Mistake:** Using only Retrieve Value and Find Extremum items because they are easiest to write. **Why it fails:** The instrument becomes a narrow graph-reading test and underrepresents higher-demand interpretation tasks.

## Quick checks for task coverage <!-- role: check -->

**Failure Sign:** Most items can be answered by reading a single mark without comparison or pattern reasoning. **Quick Check:** Tag every item with one of the eight tasks and verify all tasks appear multiple times. **Stronger Test:** Review item performance by task to ensure variability is not dominated by one task category.

## What to do if tasks are hard to operationalize <!-- role: fix -->

- Rewrite stems to explicitly request an outcome aligned to a single task category.
- Use chart types where the task is naturally supported (e.g., correlations with scatterplots).
- Add chart-specific prerequisite tasks when needed (e.g., hierarchy identification for treemaps).
- Remove tasks from chart-type pairings when the task is not suitable for that encoding in your context.
