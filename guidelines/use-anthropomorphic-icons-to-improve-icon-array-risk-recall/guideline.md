## Prefer people-like icon shapes in icon arrays for recall <!-- role: advice -->

Use anthropomorphic (people-like) icons rather than abstract shapes when an icon array must support later recall of a risk percentage.

## Anthropomorphism supports memory for risk magnitude <!-- role: reason -->

More human-like shapes can attract attention and create a more meaningful mapping between the icons and the “people in the denominator,” strengthening encoding and retrieval of the numerical risk.

**Mechanism:** People-like forms increase salience and distinctiveness of individual units in the array, which can make the risk quantity easier to encode and later retrieve.

**Evidence:** Accurate recall of a displayed 10-year cardiovascular risk estimate differed by icon type, with higher recall for anthropomorphic icon arrays (restroom icons, photographs, head outlines) than for abstract icons such as blocks. [@zikmund-fisherBlocksOvalsPeople2014]

**Notes:** The improvement was primarily a reduction in overestimation errors rather than underestimation errors.

## Use when recall of a stated risk estimate matters after a delay <!-- role: context -->

- **User Goal:** Remember the risk estimate they were shown (e.g., for later discussion or decision-making).
- **Task:** Recall an integer risk percentage after intervening survey content.
- **Data:** Single-person risk estimate communicated as a percent within a 100-unit icon array.
- **Chart Setting:** Static icon array accompanied by a numeric value.
- **Audience:** Mixed numeracy and mixed graph literacy.
- **Success Criterion:** Higher proportion recalling the risk within a small tolerance (±2 percentage points).

## Exceptions for recall-focused anthropomorphic icons <!-- role: exceptions -->

**Break it when:** You cannot use people-like symbols because the icon must be purely geometric for branding or strict visual-system constraints. **Why:** The specific recall advantage documented depends on icon type variation that includes anthropomorphic forms.

## Tradeoffs of anthropomorphic icons <!-- role: costs -->

**Sacrifice:** Anthropomorphic icon sets may require more design effort and asset management than simple blocks/ovals. **Risk:** People-like icons may introduce unintended personal relevance or emotional reactions not needed for the task. **Mitigation:** Keep color, layout, denominator, and labeling constant so only icon form changes.

## Common recall-related mistakes with icon choice <!-- role: mistakes -->

- **Mistake:** Treating blocks, ovals, and people icons as interchangeable because they encode the same counts. **Why it fails:** Recall accuracy changes with icon type even when the data and array structure are identical.
- **Mistake:** Evaluating icon arrays only on immediate comprehension and ignoring later recall. **Why it fails:** The measured differences appear on delayed recall of the risk estimate.

## Quick checks for recall robustness <!-- role: check -->

**Failure Sign:** Users frequently misremember the risk as higher than what was shown. **Quick Check:** Run a short delayed recall question (e.g., after unrelated items) and compare accuracy across icon candidates. **Stronger Test:** A/B test icon types and score recall as within a fixed tolerance (e.g., ±2%).

## What to do instead if you cannot change icon type <!-- role: fix -->

- Add a short “Your risk is X%” text restatement adjacent to the array and keep it visible wherever feasible.
- Reduce competing on-screen elements around the array to avoid attention dilution at encoding.
- Use a single icon set consistently across all risk communications in the product so users learn the mapping over time.
- If recall is mission-critical, include a follow-up summary screen that repeats the numeric estimate after intervening content.
