## The Rule <!-- role: advice -->
When adding embellishments, intertwine the imagery with the data elements themselves (e.g., using an image to form the shape of the bars or the line) rather than separating the data and the illustration.

## The Logic <!-- role: reason -->
Eye-tracking data indicates that users can process "dual-coded" areas (regions containing both data and embellishment) without a significant penalty in interpretation time. In the study, users spent considerable time looking at embellishments, yet their description time and accuracy were no worse than plain charts [@bateman_useful_2010]. This suggests the imagery helped encode the chart structure (like the trend) because the image *was* the trend.

*   **The Principle:** Dual Coding.
*   **The Evidence:** Eye-tracking showed 27% of gaze time on "dual coded" areas, yet interpretation accuracy did not suffer compared to plain charts [@bateman_useful_2010].

## Where to Apply <!-- role: context -->
*   **User Goal:** Engaging the reader while simultaneously presenting data.
*   **Audience:** Lay readers or "busy" readers who need to grasp the point quickly through attraction.

## When to Break It <!-- role: exceptions -->
*   **Scenario:** High-Precision Comparison.
*   **Reason:** If the imagery distorts the geometric perception of the data (e.g., irregular shapes making height comparison difficult), accuracy may suffer, though the study found no significant error increase for the specific Nigel Holmes charts tested [@bateman_useful_2010].

## The Price <!-- role: costs -->
*   **The Sacrifice:** Design Effort.
*   **The Risk:** Requires significant artistic skill to integrate data and image without violating data integrity (e.g., axis scaling) [@bateman_useful_2010].

## Common Mistakes <!-- role: mistakes -->
*   **The Wrong Fix:** "Chart Junk" that frames the data but doesn't interact with it.
*   **Why it fails:** The benefit comes from the image encoding the *structure* of the data (e.g., a monster's teeth showing the rising trend), not just decorating the border.

## How to Check <!-- role: check -->
*   **Visual Sign:** If you remove the data bars/lines, does the image still convey the general trend (e.g., going up or down)?
*   **The Test:** Check if the "ink" used for the image is also functioning as the "ink" used for the data [@bateman_useful_2010].

## How to Fix <!-- role: fix -->
*   **Best Fix:** Hire a skilled illustrator to create a "Holmes-style" chart where the thematic object physically represents the data constraints (e.g., a shoe forming the bar in a chart about walking).
