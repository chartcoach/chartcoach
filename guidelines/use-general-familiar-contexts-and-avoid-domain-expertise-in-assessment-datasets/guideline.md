## Use general, non-specialist dataset contexts to avoid familiarity bias in literacy assessment <!-- role: advice -->

Select datasets and attribute labels with general contexts that do not require specialized expertise, so comprehension depends on the visualization rather than prior domain knowledge.

## Why context familiarity can confound literacy measurement <!-- role: reason -->

If test content relies on domain-specific concepts or unfamiliar attributes, errors can reflect content unfamiliarity rather than an inability to read the visual encoding. Using familiar, everyday contexts reduces construct-irrelevant variance and makes performance more attributable to visualization literacy.

**Mechanism:** Reducing domain-knowledge demands isolates the cognitive operations of decoding and interpreting the visual representation.

**Evidence:** VLAT visualizations were built from real-world datasets with general contexts and careful review of dataset attributes to reduce bias from context and attribute familiarity [@leeVLATDevelopmentVisualization2017].

**Notes:** Familiar context does not guarantee familiar attributes, so attribute selection needs explicit review.

## When this dataset choice rule applies <!-- role: context -->

- **User Goal:** Measure visualization literacy rather than domain expertise.
- **Task:** Pick datasets and label wording for test items and charts.
- **Data:** Realistic public datasets; avoid technical attributes that require prior instruction.
- **Chart Setting:** Standardized assessment with limited time per item.
- **Audience:** Non-experts, general population adults.
- **Success Criterion:** Scores are interpretable as visualization reading skill.

## When to break it <!-- role: exceptions -->

**Break it when:** The assessment is explicitly domain-specific (e.g., medical risk charts for clinicians). **Why:** Domain knowledge is part of the intended construct in that setting.

## Tradeoffs of using general contexts <!-- role: costs -->

**Sacrifice:** Reduced realism for specialized workplaces and fewer opportunities to assess domain-integrated reasoning. **Risk:** Overfitting to “trivia-like” topics that feel unimportant to stakeholders. **Mitigation:** Use real datasets from public sources while keeping contexts broadly accessible.

## Common dataset selection mistakes <!-- role: mistakes -->

**Mistake:** Using a familiar topic but keeping technical attributes (e.g., specialized measurements) in labels. **Why it fails:** Attribute unfamiliarity can dominate errors even when the chart is readable.

## Quick checks for context bias <!-- role: check -->

**Failure Sign:** Participants report confusion about terms/attributes more than about reading the chart. **Quick Check:** Ask a small pilot group to paraphrase what each attribute means without chart reading. **Stronger Test:** Collect qualitative feedback on which terms required outside knowledge and replace them.

## What to do if domain knowledge is leaking into the test <!-- role: fix -->

- Replace specialized attribute names with plain-language equivalents that preserve meaning.
- Swap the dataset for a different one that supports the same chart type and tasks with simpler semantics.
- Add brief definitions for necessary terms if they must remain (while keeping the focus on the chart).
- Remove items whose success depends on external knowledge rather than the visual encoding.
