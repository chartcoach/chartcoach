## The Rule <!-- role: advice -->

Do not use visualization only for postprocessing; couple visual interfaces directly to simulation and automated analysis so users can interactively steer analysis.

## The Logic <!-- role: reason -->

The paper states current practice uses visualization mainly in postprocessing, but argues a “more promising trend” is integrating visualization tools with simulation and automated analysis, consistent with visual analytics’ interactive analysis approach [@kohlhammerVisualizationPolicyModeling2012]. This works by combining computer-scale processing (aggregation/structuring) with human pattern recognition through interactive visual displays.

## Where to Apply <!-- role: context -->

- **User Goal:** Explore scenarios, set model parameters, and iteratively refine understanding of policy impacts.
- **Data Type:** Data generated by simulations, opinion mining, optimization, or other automated methods.
- **Audience:** Policy analysts who must use complex computational models without being experts in those disciplines.

## When to Break It <!-- role: exceptions -->

- **Scenario:** The underlying analysis is fixed, validated, and must not be interactively changed (for governance, audit, or reproducibility constraints).
- **Reason:** Steering parameters visually could violate process constraints even if it improves exploration.

## The Price <!-- role: costs -->

- **The Sacrifice:** Higher implementation complexity (tight coupling between UI and models).
- **The Risk:** Users may misinterpret exploratory runs as definitive results if provenance and run context aren’t managed.

## Common Mistakes <!-- role: mistakes -->

- **The Wrong Fix:** Showing only final outputs of models (static charts or screenshots) without controls.
- **Why it fails:** It preserves the postprocessing-only pattern the paper identifies as limiting for policy modeling [@kohlhammerVisualizationPolicyModeling2012].

## How to Check <!-- role: check -->

- **Visual Sign:** Users can view model outputs but cannot change inputs, rerun scenarios, or compare runs within the interface.
- **The Test:** Try to answer “What happens if we change X?” without leaving the visualization; if you can’t, the coupling is missing.

## How to Fix <!-- role: fix -->

- **Quick Fix:** Add parameter controls and scenario selectors that trigger recomputation and update visuals.
- **Best Fix:** Build a visual-analytics loop where computation summarizes data, users spot patterns, and interaction requests deeper computation for impact analysis [@kohlhammerVisualizationPolicyModeling2012].
