## Pretrain components before the full system explanation <!-- role: advice -->

Provide learners brief pretraining on the names and behaviors of key components before presenting the narrated animation of the whole causal system.

## Why pretraining reduces essential load in the main lesson <!-- role: reason -->

Constructing a mental model of a system requires building representations of individual components and also building the causal chain linking them. Without prior component knowledge, learners must do both at once during the main presentation, which can exceed working memory capacity; pretraining shifts some essential processing earlier so the main lesson can focus more on causal integration.

**Mechanism:** Pretraining builds component-level schemas, reducing the working memory demand of identifying and understanding parts during causal-model construction.

**Evidence:** Learners showed higher transfer when a narrated animation was preceded by pretraining on component names/behaviors than without pretraining, consistent with a pretraining effect [@mayerNineWaysReduce2003].

**Notes:** This approach is intended for high intrinsic complexity where simplification is not feasible.

## When component understanding is a bottleneck <!-- role: context -->

- **User Goal:** Understand how a multi-part mechanism works.
- **Task:** Build a causal model linking component interactions.
- **Data:** Many components with distinct functions and relations.
- **Chart Setting:** Narrated animation explaining a mechanism (e.g., mechanical or physical systems).
- **Audience:** Learners unfamiliar with the components and terminology.
- **Success Criterion:** Better transfer on novel problem-solving questions.

## When pretraining is unnecessary <!-- role: exceptions -->

**Break it when:** Learners already know the components and their functions. **Why:** The added instruction may not reduce essential processing and may waste time.

## Tradeoffs of pretraining <!-- role: costs -->

**Sacrifice:** Extra instructional time and planning for a prerequisite module. **Risk:** Pretraining can feel disconnected if not aligned to the later causal explanation. **Mitigation:** Keep pretraining focused on exactly the components used in the main lesson.

## Common pretraining pitfalls <!-- role: mistakes -->

**Mistake:** Pretraining with extra facts not needed for the later causal explanation. **Why it fails:** It can increase processing demands without supporting the causal model construction.

## Checks for whether pretraining is needed <!-- role: check -->

**Failure Sign:** Learners cannot name parts or describe what parts do, even if they recall isolated steps. **Quick Check:** Ask learners to label components before the main lesson; frequent failures indicate a component bottleneck. **Stronger Test:** Compare transfer outcomes for pretraining versus no-pretraining groups.

## What to do if you cannot pretrain <!-- role: fix -->

- Segment the main lesson so learners can digest component information as it appears.
- Signal component introductions with cues that highlight names and relevant visual elements.
- Weed out embellishments so learners can allocate capacity to component understanding.
- Synchronize words and pictures so component descriptions and depictions co-occur.
