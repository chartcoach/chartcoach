## Guidance

Use a more spacious, taller row height for tables with few rows, and a more compact, shorter row height for tables with many rows.

## Why

The optimal row height depends on the table's length.
- **Short Tables:** A generous row height creates a clean, uncluttered, and aesthetically pleasing look. It makes each row easy to read.
- **Long Tables:** A compact row height increases information density, allowing more rows to fit on the screen at once. This makes it easier for users to scan and compare values across multiple rows without excessive scrolling.

## When it applies

- When designing a table, consider the expected number of rows.
- For short tables (e.g., < 10 rows), use a spacious layout.
- For long tables (e.g., > 20 rows), use a compact layout.

## Exceptions

- If the rows must contain taller content, such as multi-line text or images, a compact layout will not be possible regardless of the number of rows.
- Accessibility guidelines for touch targets might require a minimum row height, especially for interactive tables.

## Trade-offs

- A compact layout can feel cramped if not designed carefully, potentially reducing the legibility of individual rows.
- A spacious layout on a long table wastes screen real estate and forces excessive scrolling.

## Signs of Trouble

- **Endless Scrolling:** A long table with very tall rows requires a frustrating amount of scrolling to see all the data.
- **Wasted Space:** A short table with very compact rows looks cramped and lost in a sea of white space.
- **Comparison Difficulty:** In a long, spacious table, it's hard to compare row 5 with row 15 because they are too far apart on the screen.

## How to Improve

- **Action:** In your CSS or table styling tool, define different style classes for compact and spacious tables.
    - For `table.compact`, use smaller padding within cells (e.g., `padding: 4px 8px;`).
    - For `table.spacious`, use larger padding (e.g., `padding: 12px 8px;`).
- Apply the appropriate class based on the data you are presenting.
