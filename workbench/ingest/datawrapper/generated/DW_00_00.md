## Guidance

When chart elements like bars or columns are already clearly distinguished by their position, use a single color for all of them.

## Why

Using multiple colors when position already separates elements is redundant. It adds visual noise and increases cognitive load by forcing the viewer to process color information that has no meaning. A single color creates a cleaner, more professional aesthetic and helps the viewer focus on what matters: the data's shape and values.

### Core Principle
Reduce the cognitive work required to decode your visualization. Every unnecessary visual element, including meaningless color, is a potential distraction.

## When it applies

- Simple bar and column charts.
- Line charts where lines do not cross and are easily distinguishable.
- Any chart where elements are separated by space, and color is not used to encode another variable.

## Exceptions

- When color is used to encode a second data variable (e.g., using a diverging palette on bars to show deviation from a baseline).
- When you intentionally use color to highlight a specific category to guide the viewer's attention.
- When categories need to be referred to by name in the accompanying text (e.g., "...as seen in the blue bar"). However, direct labeling is often a better solution for this.

## Trade-offs

- **Gained:** Reduced clutter, increased focus on data shapes, more professional aesthetic.
- **Sacrificed:** Ability to refer to elements by color; potentially less "eye-catching" to some, though often more effective.

## Signs of Trouble

- **The Rainbow Effect:** A bar chart where every bar is a different color from a default software palette, but the colors don't correspond to any meaningful grouping or variable.
- **Cognitive Dissonance:** A viewer asks "What do the different colors mean?" and the answer is "Nothing."

## How to Improve

- **Quick Fix: Go Monochrome.** Select all the elements (e.g., all bars in a bar chart) and assign them the same color. A neutral gray or a single brand color works well.
