## Guidance

When a user must remember and compare multiple values, prioritize reducing the number of data points they need to hold in memory. This is often more effective than trying to select the "best" visual channel based on classic perceptual rankings.

## Why

Human visual working memory is severely limited, typically holding only about 3-4 items at a time. When a chart displays more items than this limit, a viewer's ability to accurately recall the values plummets, regardless of how they are encoded visually. The cognitive load of remembering the extra items overwhelms the subtle perceptual advantages of one channel over another.

### Core Principle

Cognitive limitations, such as working memory capacity, can be a more powerful constraint on visualization effectiveness than perceptual accuracy alone. Design choices should first and foremost respect these cognitive bottlenecks.

## When it applies

-   When users need to compare values between different charts (e.g., in a dashboard or small multiples).
-   When users must remember values from a visualization to compare them to information in a separate text or table.
-   When designing any visualization that displays more than 4-5 individual, non-aggregated data points that users are expected to recall.

## Exceptions

-   For simple, direct comparison tasks involving only two values within a single, static view (e.g., judging the ratio of two bars side-by-side). In these cases, memory is not a significant factor, and classic perceptual rankings are more likely to apply.
-   When the task is "gist" perception, like judging the average or overall trend, rather than recalling individual values.

## Trade-offs

-   Reducing the number of marks may require aggregating or filtering data, which can hide important details, outliers, or the overall distribution shape.
-   Using techniques like faceting (small multiples) to show fewer marks per chart can take up more screen space.

## Signs of Trouble

-   **Overwhelm:** Users report that the chart feels "too busy" or "overwhelming."
-   **High Error Rates:** When asked to recall or compare values, users make large, inconsistent errors.
-   **Slow Performance:** Users take a long time to find or compare information, often re-scanning the chart multiple times.
-   **Reliance on a Legend:** Users have to constantly look back and forth between the data marks and a legend to make comparisons, indicating a high memory load.

## How to Improve

-   **Quick Approach: Highlighting.** Use color, size, or opacity to de-emphasize non-essential data points and draw attention to a small, critical set of marks (fewer than 5). This guides the user to focus on a manageable subset.
-   **Moderate Approach: Faceting.** Break a single complex chart into several "small multiple" charts, each showing a different subset of the data. This keeps all data visible but reduces the number of items that need to be compared within any single view.
-   **Comprehensive Approach: Aggregation or Filtering.** Instead of showing all individual data points, aggregate them into summary statistics (e.g., show a bar chart of averages instead of a dot plot with all points). Alternatively, provide interactive controls to let users filter the data to a smaller, more relevant subset.

## Guidance

When designing visualizations for tasks that require accurate recall of absolute values, be aware that viewers are likely to systematically misremember them. They tend to overestimate small values and underestimate large values, pulling their memories toward the middle of the range.

## Why

This bias is likely caused by a combination of perceptual and cognitive factors. Human memory tends to compress ranges, a phenomenon related to "central tendency bias," where judgments are pulled toward the average of a set. When recalling a value from a chart, the memory of that value is biased toward the center of the axis or the average of the other values present.

### Core Principle

Human memory for visualized data is not a perfect recording; it is a biased reconstruction influenced by the context of other values and the scale itself.

## When it applies

-   In any visualization where the precise recall of absolute quantitative values is important for decision-making.
-   When users must compare a value seen in a chart to a standard or threshold remembered from elsewhere.
-   In dashboards or reports where users may glance at a chart and make decisions based on their memory of it later.

## Exceptions

-   When the primary task is to judge relative ranks or general trends, and the accuracy of absolute values is not critical.
-   When all data points are clustered in the middle of the range, as the bias is weakest for median values.

## Trade-offs

-   Adding elements to counteract this bias, such as data labels or reference lines, can increase visual clutter.
-   Guiding attention to specific values might cause users to neglect other parts of the data.

## Signs of Trouble

-   **Skewed Decisions:** Decisions made based on recalled chart values are consistently skewed (e.g., risks associated with high values are downplayed, or the significance of low values is inflated).
-   **Misremembering Extremes:** When questioned, users consistently recall extreme values as being less extreme than they actually were.
-   **Failed Validations:** When a user's recalled value is checked against the actual data, there is a systematic pattern of overestimation for low values and underestimation for high values.

## How to Improve

-   **Quick Approach: Add Data Labels.** For the most critical data points (especially highs and lows), add direct text labels. This provides an escape hatch, allowing users to read the exact value instead of relying on their biased perception and memory.
-   **Moderate Approach: Add Reference Lines.** Add static reference lines for key statistical markers like the mean, median, or a critical threshold. These lines provide explicit anchors that can help reduce the bias from viewers mentally "guessing" the center of the range.
-   **Comprehensive Approach: Use Interactive Highlighting.** Allow users to hover over or click on a mark to reveal its exact value and its relationship to other data points (e.g., "This value is 35% above the average"). This encourages active exploration rather than passive, memory-based judgment.

## Guidance

When a user's task is to remember and compare a small set of quantitative values (e.g., 3-5 items), and the primary goal is to minimize systematic error (bias), consider using a length-based encoding (e.g., misaligned bars or a dot plot) instead of a standard position-based bar chart.

## Why

Classic experiments show position on a common scale (bar charts) is best for *perceptual* accuracy in direct, side-by-side comparisons. However, this study suggests that for *memory-based* tasks, the story changes. Storing and recalling multiple positions may be more susceptible to systemic bias (over/underestimation) than storing and recalling multiple lengths. Length encoding appeared to be more robust against this type of memory distortion.

### Core Principle

The optimal visual channel for a task depends on the cognitive processes involved (e.g., perception vs. memory), not just on a static perceptual hierarchy. Rankings derived from one type of task may not generalize to others.

## When it applies

-   When the main goal is to ensure that users' recalled judgments are, on average, accurate (low bias), even if they are less consistent (lower precision).
-   When designing charts where users must remember a few key values to compare them against each other, such as in a series of small multiples.
-   For tasks involving 4 to 8 data points, where the effect was observed.

## Exceptions

-   For simple two-value, non-memory-based comparisons, where position encoding is still likely superior.
-   When precision (consistency of judgment) is more important than accuracy (low bias). The same study found other channels, like area, produced more precise (though more biased) responses.
-   When a common baseline is essential for the task. By definition, length-based charts like misaligned bars or Gantt charts lack a common starting point.

## Trade-offs

-   Length judgments are generally less precise (more variable) than position judgments, even if they are less biased in this specific context. Users' responses may be more scattered around the true value.
-   Charts that rely on length encoding without a common baseline (like misaligned bars) can make part-to-whole comparisons impossible and other comparison tasks more difficult.

## Signs of Trouble

-   **Systematic Bar Chart Bias:** Users consistently underestimate the average of a set of bars or show other predictable patterns of misestimation when recalling values from a bar chart.
-   **Context-Dependent Errors:** The errors users make in recalling bar heights change significantly depending on the heights of surrounding bars.

## How to Improve

-   **Quick Approach: Switch to a Dot Plot.** Instead of a bar chart, use a dot plot. This still uses position but de-emphasizes the length of the bar, which may mitigate some biases.
-   **Moderate Approach: Use Misaligned Bars.** If a common baseline is not critical, switch from a standard bar chart to a misaligned bar chart (where bars start at different points). This forces a length judgment, which may be less biased for recall.
-   **Comprehensive Approach: Test and Validate.** If low bias is critical for your application, run a small user study comparing a standard bar chart with a length-based alternative (like a dot plot or misaligned bars) for your specific task to see which yields more accurate recalled judgments from your users.

## Guidance

If the primary goal for a multi-item recall task is *consistency* (high precision) of judgment, and you can tolerate systematic *inaccuracy* (high bias), then area-based encodings (like bubble charts) may perform better than position or length. This is a counter-intuitive finding that should be applied with extreme caution.

## Why

This result is surprising and contradicts the vast majority of perception literature, which focuses on accuracy (low bias). The study found that while participants' recalled values from area-encoded charts were more systematically wrong (more biased), the responses were less scattered (had lower variance). This suggests that while area is a poor channel for judging absolute magnitude, it may produce more consistent (if incorrect) memories, possibly due to how ensembles or "gists" of sizes are stored in memory.

### Core Principle

Perceptual performance has multiple dimensions, including accuracy (bias) and consistency (precision). Optimizing for one may come at the expense of the other. The "best" visual channel depends entirely on which of these dimensions is more critical for the task at hand.

## When it applies

-   In rare scenarios where the consistency or stability of a user's judgment across multiple viewings is more important than its absolute accuracy.
-   For tasks involving the recall of a small set of items (e.g., 4 marks), where this specific effect was observed.
-   When exploring novel interfaces where the goal is to understand the trade-offs between different perceptual metrics.

## Exceptions

-   **In almost all common use cases.** Accuracy (low bias) is typically the most important goal in data visualization. Since area encodings perform very poorly on accuracy, they should be avoided for most quantitative comparison and lookup tasks. This guideline is an exception, not the rule.

## Trade-offs

-   **The primary trade-off is severe:** You gain consistency at the cost of accuracy. Users will be more consistently wrong. This is a dangerous trade-off in almost all analytical contexts where decisions are based on data.
-   Area judgments are also notoriously susceptible to perceptual biases (e.g., the Ebbinghaus illusion) and non-linear mapping between data and perceived size.

## Signs of Trouble

-   **Inconsistent Judgments:** When recalling values from a bar or line chart, users' responses are highly variable and scattered.
-   **Accuracy is Paramount:** The task requires users to make accurate judgments of absolute or relative value, and any systematic bias could lead to poor decisions. (This is a sign *not* to use this guideline).

## How to Improve

-   **Apply with Extreme Caution:** If you face a unique situation where precision is paramount and bias is acceptable, you could experiment with switching from a position-based chart (bar chart) to an area-based one (bubble chart).
-   **Acknowledge the Trade-off:** If you must use this approach, explicitly inform the user about the potential for biased judgments. For example, add annotations or text explaining that the chart is for judging relative patterns of consistency, not for making accurate magnitude comparisons.
-   **Default to Position/Length:** For virtually all standard visualization tasks, stick with channels that optimize for accuracy, like position and length. This guideline highlights a fascinating finding about perception but is not a general-purpose recommendation.
