## Guidance

When encoding different categories of points in a scatterplot for a mean comparison task, use a salient visual channel like color (hue or luminance) instead of a less salient one like shape.

## Why

Humans can select and process groups of objects based on color more efficiently and accurately than based on shape. This pre-attentive ability to "filter" by color allows for a more rapid and reliable estimation of a group's average position, even in a cluttered display. Shape is a less "salient" cue, meaning it requires more cognitive effort to group and process, leading to lower performance on aggregation tasks.

### Core Principle

Visual cues vary in their salience, or their ability to support rapid attentional selection. More salient cues like color lead to better performance in aggregation tasks because they make the initial perceptual grouping step easier and more accurate.

## When it applies

- When viewers need to compare the average value of two or more categories presented within a single scatterplot (e.g., "which group is higher on average?").
- When you have multiple visual channels available (e.g., color, shape, size) and need to decide which to use for encoding categorical data.

## Exceptions

- If color is already used to encode a different, more important variable.
- When designing for an audience with known color vision deficiencies and a color-blind safe palette cannot be used. In this scenario, relying on shape is a necessary, though less effective, alternative. Always best to use both if accessibility is a primary concern.

## Trade-offs

- Using color for categories means it cannot be used to encode a continuous quantitative variable (e.g., via a sequential color map).
- Over-reliance on color without providing a redundant channel (like shape or labels) can create accessibility barriers for users with color vision deficiencies.

## Signs of Trouble

- **The Squint Test:** If you squint at the chart, is it difficult to distinguish the different groups of points? If they blur together, your chosen encoding may not be salient enough.
- **Slow Grouping:** Viewers take a long time to determine which points belong to which category before they can even start comparing the averages.
- **Shape Ambiguity:** It's difficult to quickly tell the difference between the shapes being used (e.g., squares vs. slightly rounded squares).

## How to Improve

- **Quick Fix: Increase Shape Contrast.** If you must use shapes, ensure they are highly distinct and easy to tell apart (e.g., circles vs. plus-signs, not circles vs. squares).
- **Comprehensive Redesign: Switch to Color.** Recode the categories using a perceptually distinct and accessible color palette (e.g., from tools like ColorBrewer or Viz Palette). This will leverage the visual system's superior ability to group items by color.

## Guidance

For tasks like comparing the average value of categories in a scatterplot, do not use multiple visual channels (e.g., both color and shape) to represent the same information. A single, sufficiently salient channel is just as effective and less complex.

## Why

The human visual system typically selects and groups items by filtering on a single feature at a time (e.g., "all the red things" or "all the circles"). Adding a second, redundant feature (e.g., making all red things *also* circles) doesn't make this filtering process faster or more accurate because the selection is already made based on the first feature. Since there's no performance benefit, adding redundant encodings creates unnecessary visual complexity and "uses up" a visual channel that could have been used to encode a different dimension of the data.

### Core Principle

Effective visualization prioritizes clarity and efficiency. If an additional visual element does not improve perceptual performance, it adds unnecessary complexity and should be omitted or used to encode new information.

## When it applies

- When designing scatterplots where the primary task is to compare aggregate properties (like the mean) of different categories.
- When you are tempted to "reinforce" a categorical encoding by using a second visual variable for the same data.

## Exceptions

- **Accessibility:** When designing for broad accessibility, redundant coding is a best practice. Using both color and shape ensures that users with color vision deficiencies can still distinguish the categories. In this context, the accessibility benefit is critical and outweighs the lack of a performance gain for other users.
- **Very Low Salience:** If the primary encoding channel is very weak or subtle (e.g., very similar shapes), a redundant cue might help, though choosing a more salient primary cue is a better solution.

## Trade-offs

- **Simplicity vs. Redundancy for Accessibility:** Following this guideline strictly creates a simpler chart but may exclude users with certain vision impairments. The main trade-off is between visual minimalism and inclusive design.

## Signs of Trouble

- **Visual Overload:** The chart feels unnecessarily complex, with multiple visual properties (like color and shape) changing in perfect lock-step, conveying only one piece of information.
- **Wasted Channel:** A visual channel like `shape` is used to redundantly encode a category already clearly shown by `color`, when that `shape` channel could have been used to display another attribute of the data.
- **Legend Clutter:** The legend becomes more complex, requiring the user to process multiple redundant cues (e.g., "Blue Circle = Group A", "Orange Triangle = Group B").

## How to Improve

- **Simplify and Re-purpose:** Remove the redundant encoding. If categories are encoded by both color and shape, decide which is the primary channel (likely color). Make the other channel uniform for all categories (e.g., all points become circles). Then, consider using the newly freed visual channel to encode a different, useful variable from your dataset.
- **Prioritize for Accessibility:** If accessibility is a key concern, intentionally use redundant coding. Pair a color encoding with a distinct shape encoding to ensure all users can interpret the data.

## Guidance

When designing multi-dimensional scatterplots, feel confident using a secondary visual channel (e.g., shape) to encode a different variable, even if it is irrelevant to the primary comparison task based on another channel (e.g., color). The presence of this "irrelevant" information does not significantly hinder a user's ability to perform aggregate comparisons.

## Why

The visual system is adept at selective attention, allowing viewers to "tune in" to a specific feature (like color) while effectively ignoring others (like shape). When asked to compare the average position of the "blue" and "orange" groups, viewers can filter for color and are not significantly distracted by the fact that the points also have varying shapes. This allows for the efficient layering of multiple data dimensions in a single chart without compromising the integrity of comparisons on any single dimension.

### Core Principle

Selective attention allows viewers to process one visual channel while suppressing others. This makes it possible to create dense, multi-dimensional visualizations where different channels encode different variables without causing significant interference.

## When it applies

- When creating a scatterplot that needs to encode three or more variables (e.g., X-position, Y-position, Category A, Category B).
- When you are concerned that adding more information to your plot will create "clutter" and make it harder to read. This evidence suggests that, up to a point, layered information is not as detrimental as one might think.

## Exceptions

- **Extreme Visual Complexity:** The study found that performance *did* degrade when *both* a conflicting cue *and* an extra distractor class were added simultaneously. This suggests there is a tipping point where the overall visual complexity becomes too high for selective attention to function effectively. Avoid layering too many conflicting channels and classes at once.
- **Highly Salient Distractor:** If the irrelevant cue is significantly more salient than the primary cue (e.g., large size variation distracting from subtle color differences), it may cause interference.

## Trade-offs

- **Information Density vs. Simplicity:** While layering information is perceptually feasible, it inherently increases the cognitive load required to understand the chart's legend and overall meaning. The viewer has to learn what each visual channel represents. The trade-off is between showing more data in one chart and maintaining simplicity.

## Signs of Trouble

- **Combined Complexity:** The chart contains multiple, unrelated categorical encodings (e.g., by color, shape, and texture) AND several different classes of data points, making the overall display feel overwhelming and dense.
- **Distraction by Salience:** A secondary, "irrelevant" encoding is so visually prominent (e.g., a few very large points) that it draws attention away from the primary task.

## How to Improve

- **Use a Visual Hierarchy:** Ensure the visual channel used for the most important comparison is also the most salient (e.g., use strong color for the primary categories). Use less salient channels (like shape or texture) for secondary information.
- **Simplify if Overwhelmed:** If a chart combines too many sources of complexity (conflicting cues + extra classes), simplify it. Consider splitting it into two separate charts or removing the least important dimension of the data.
