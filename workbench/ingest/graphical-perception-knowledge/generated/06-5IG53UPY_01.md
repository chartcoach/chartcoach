## Guidance

Avoid using a continuous color gradient (e.g., light blue to dark blue) to encode a quantitative, continuous variable like elapsed time when users need to perform precise lookups.

## Why

Humans are generally poor at accurately mapping a specific shade from a continuous color gradient back to a precise quantitative value. This "inverse lookup" is a perceptually difficult task. Viewers can get a qualitative sense of progression (e.g., "this is near the beginning"), but they cannot reliably identify a specific value (e.g., "this is the 68% mark"). This limitation leads to high error rates and low confidence.

### Core Principle

Visual channels have different perceptual properties. While color is good for drawing attention or showing categorical differences, position and length are far superior for making precise quantitative judgments.

## When it applies

- When visualizing a continuous quantitative variable like elapsed time on a 2D path.
- When the user's task is to retrieve a specific value (e.g., "Find the point where 50% of the time has elapsed").
- When accuracy in reading the time value is important.

## Exceptions

- When only a rough, qualitative sense of time progression is needed (e.g., showing a general flow from "beginning" to "middle" to "end") and no precise lookup is required.
- When color is being used as a redundant channel to reinforce another, more effective primary encoding for time.

## Trade-offs

- Following this guideline means you cannot use the color channel for encoding time, freeing it up for another variable (like speed or a category).
- Avoiding color for time may require using an encoding (like segment length) that can add visual complexity (tick marks).

## Signs of Trouble

- **The "Guessing Game":** Viewers are unable to confidently locate a specific time point and resort to guessing.
- **Inaccurate Readings:** When tested, users' estimates of time values from the color gradient are consistently off by a large margin.
- **Slow Performance:** It takes users a long time to attempt a lookup, often because they are scanning back and forth between the color legend and the path.
- **Accessibility Failure:** Users with color vision deficiency find it even more difficult, or impossible, to perceive the gradient.

## How to Improve

- **Quick Fix: Add Annotations.** Keep the color gradient if it's required for other reasons, but add clear, explicit labels or tick marks for key time points (e.g., 25%, 50%, 75%). This provides a perceptual "escape hatch" for users who need accuracy.
- **Moderate Approach: Switch to Size.** Encode time using stroke width (size). Perin et al. (2018) found this was more accurate than color for time-retrieval tasks. The path would get progressively thicker over time.
- **Comprehensive Approach: Switch to Segment Length.** The most effective solution is to encode time using segment length (tick marks at constant time intervals). This was the most accurate encoding in the study and is the recommended best practice.
