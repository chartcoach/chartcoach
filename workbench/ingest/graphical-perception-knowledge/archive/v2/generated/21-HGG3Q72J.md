## Guidance

To help users see the overall 'gist' or average of a dataset, encode values using **color**. To help them find specific details like the highest or lowest value, encode values using **position**.

## Why

Our visual system processes these channels differently. We are better at rapidly estimating summary statistics (like the mean or variance) from color distributions, as our brain can quickly average the color information. In contrast, we are more precise at identifying specific boundary values (like the minimum or maximum) when they are encoded by position (e.g., the peak of a line). This creates a fundamental trade-off: the visual encoding that is best for seeing the big picture is not the best for finding individual details.

## When it applies

- When visualizing data distributions, such as time series, where users might need to perform both summary tasks (e.g., "What's the average value this month?") and identification tasks (e.g., "What was the single highest value?").
- When choosing between chart types that prioritize one channel over the other, such as a **line chart** (position) versus a **heatmap** (color).

## Exceptions

- When the user's task is exclusively one or the other. If the audience only needs to find the peak value, a line chart is sufficient. If they only need to see the average pattern, a heatmap is ideal.
- When color or position channels are already reserved for other, more critical data variables in the visualization.

## Trade-offs

- **Clarity vs. Gist:** By using position to optimize for identifying specific values, you may make it harder for users to quickly judge the average of a noisy dataset.
- **Gist vs. Clarity:** By using color to optimize for summary judgments, you sacrifice the ability for users to precisely and quickly locate the single highest or lowest point without careful scanning or tooltips.

## Evaluate

- [ ] Does the chart use a positional encoding (like a line or bar chart) but the primary task is to judge an average or overall pattern?
- [ ] Does the chart use a color encoding (like a heatmap) but the primary task is to find the exact minimum or maximum value?
- [ ] Do users report that it's easy to see the trend but hard to find the peak, or vice-versa? This may signal a mismatch between encoding and task.

## Repair

1.  **Prioritize the primary task.** Choose the chart type that matches the most important user goal. If finding the peak is critical, use a line chart. If seeing the average pattern is most important, use a heatmap.
2.  **Provide multiple views.** If both tasks are equally important, allow users to switch between a line chart and a heatmap of the same data. This empowers them to use the best tool for the job.
3.  **Use small multiples.** Instead of one complex chart, you could show a large line chart for detail and a small, simplified heatmap or sparkline alongside it to provide the summary context.
