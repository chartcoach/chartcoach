## Guidance

You can layer additional visual information onto multi-class scatterplots—even if it's redundant, conflicting, or adds distracting elements—without significantly harming a viewer's ability to compare the average value of the main classes.

## Why

The human visual system is surprisingly robust at performing 'visual aggregation' tasks, like judging the average position of a group of points. When asked to compare the means of different classes (e.g., "which group is higher on average?"), viewers can effectively filter out irrelevant information like extra classes, random shapes, or even an increased number of data points. This allows them to focus on the primary comparison task without a significant drop in accuracy.

## When it applies

- When using scatterplots to compare the average value (mean) of two or more distinct classes of data.
- When you need to encode a primary categorical variable (e.g., using color) and want to layer a secondary variable (e.g., using shape).
- When your chart includes additional data classes that are not part of the primary comparison but provide useful context.
- When the number of data points per class increases. Performance does not degrade and may even slightly improve.

## Exceptions

- **Extreme Complexity:** If the added encodings or distractor classes are so numerous or visually similar that they make the primary classes indistinct from each other, performance will degrade. For example, using a dozen different, poorly-chosen colors would make it hard to isolate any single one.
- **Different Tasks:** This guidance is specific to aggregate tasks like comparing averages. It may not apply to tasks requiring precise identification of individual points, where clutter can be more detrimental.
- **Weak Encodings:** The primary comparison should use a salient visual channel. For example, color is more effective for this task than shape. Relying on a weak channel for the primary comparison will result in poorer performance overall.

## Trade-offs

- While perceptually robust, adding layers does increase the visual density of a chart. This might be perceived as less aesthetically pleasing or more intimidating to some audiences, even if their task performance isn't negatively affected.

## Evaluate

- [ ] The design uses multiple separate charts to show different attributes instead of layering them onto a single scatterplot for fear of 'clutter'.
- [ ] A secondary data attribute is omitted entirely from the visualization to keep it 'clean', even though it could provide useful information.

## Repair

1.  **Combine separated charts.** Instead of a chart of `(X, Y)` by color and a separate chart of `(X, Y)` by shape, combine them into one chart where color encodes one category and shape encodes another.
2.  **Add contextual data.** Feel free to include contextual data points or "distractor classes" on the same plot rather than omitting them, as long as the primary classes remain visually distinct.
3.  **Prioritize the primary encoding.** Use a perceptually strong visual channel like color for the main comparison you want viewers to make. Layer weaker channels like shape for secondary information.
