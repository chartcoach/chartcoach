## Guidance

Recognize that there is no single 'best' colormap for all tasks on continuous quantitative maps. Instead, choose a colormap that is optimized for the viewer's primary analytical task, or provide multiple options if several tasks are critical.

## Why

Different analytical tasks rely on different perceptual processes, which are supported by different colormap characteristics.
1.  **Quantity Estimation** (reading a value) is hindered by simultaneous contrast effects, which are best counteracted by high hue variation (e.g., rainbow).
2.  **Pattern Perception** (seeing shape in complex data) relies on shading cues, which are best provided by structured luminance gradients (e.g., a diverging coolwarm scheme).

Using a single, general-purpose colormap (like a sequential or spiral ramp) results in sub-optimal performance for both of these critical tasks. Therefore, the colormap should be treated as a task-dependent tool, not a fixed data property.

### Core Principle

Visual encodings should be optimized for the specific perceptual task the viewer is performing, as different tasks have different perceptual requirements.

## When it applies

- When designing a visualization or system for analyzing continuous quantitative maps (e.g., weather, climate, or other scientific data).
- When the audience needs to perform multiple distinct types of analysis on the same map, such as reading exact values at some times and identifying structural features at others.

## Exceptions

- **Single-Task Visualizations:** If a visualization is designed to support only one specific task (e.g., it is always used for quantity lookup), then a single, optimized colormap is sufficient and appropriate.
- **Strict Brand/Style Guides:** If organizational standards rigidly enforce a single color palette, it may not be possible to offer multiple task-based options.

## Trade-offs

- **Increased Interface Complexity:** Providing users with controls to switch colormaps adds an element to the UI that must be designed, taught, and maintained.
- **Violates Simplicity:** This approach moves away from the simple "one size fits all" ideal and requires the designer and user to be more thoughtful about the analytical process.

## Signs of Trouble

- **One-Size-Fits-All Design:** A single, all-purpose colormap (e.g., greyscale, viridis) is used for an application that needs to support both accurate value lookups and fine-grained pattern analysis.
- **User Complaints:** Users express frustration that they either can't read exact values accurately or that they can't see the important details and patterns in the data.

## How to Improve

- **Quick Fix: Prioritize the Primary Task.** Identify the single most critical and frequent task your users perform. Choose a colormap optimized for that task and accept the trade-offs for other, less critical tasks. Clearly document this choice and its reasoning.
- **Moderate Approach: Provide Separate, Labeled Views.** If an interactive control is too complex, provide two static views of the same map side-by-side: one with a colormap for quantity estimation (labeled "For Reading Values") and one for pattern perception (labeled "For Seeing Patterns").
- **Comprehensive Approach: Implement Task-Based Controls.** In an interactive visualization, add a simple control (e.g., a dropdown or radio buttons) that allows the user to switch between task-optimized colormaps. Label the options by their purpose, not just their name (e.g., "Mode: Read Values" vs. "Mode: See Patterns").
