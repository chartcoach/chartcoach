```md
## Guidance

When creating multiclass scatterplots where viewers need to compare aggregate properties like the average value of different groups, encode the categories using color (hue) rather than shape.

## Why

Color is a more salient and pre-attentive visual feature than shape. This allows the human visual system to select and group items belonging to a specific category more quickly and efficiently, which is a prerequisite for performing the subsequent (and more difficult) task of judging the group's average position. Using a weaker cue like shape leads to lower accuracy.

### Core Principle

Visual channels are not created equal; some are perceptually "stronger" than others for certain tasks. For categorical grouping and selection, color is more potent than shape.

## When it applies

- When creating a multiclass scatterplot.
- When a primary task is for viewers to compare aggregate statistics (e.g., "Which group is higher on average?") between two or more categories.

## Exceptions

- **Accessibility:** If the visualization must be accessible to users with color vision deficiencies, shape becomes a critical encoding channel. In this case, use distinct shapes as the primary or redundant encoding.
- **High Cardinality:** If you have too many categories for a perceptually distinct color palette (typically > 8-10), you may be forced to use shape or other channels, though with reduced effectiveness for this task.

## Trade-offs

- **Accessibility vs. Performance:** Prioritizing color for maximum perceptual performance for the general population comes at the cost of excluding users with color vision deficiency. The best practice is often to use redundant encoding (both color and shape) to serve both goals, even if it doesn't boost performance for non-impaired users.

## Signs of Trouble

- **Task Errors:** Viewers consistently make errors when asked which category has a higher or lower average value.
- **Slow Interpretation:** Viewers take a long time to answer questions about group averages, suggesting they are struggling to segment the classes.
- **Visual "Soup":** When encoded by shape, the different categories do not visually "pop" from one another and instead blend into a uniform field of marks.

## How to Improve

- **Quick approach:** If using shape, ensure the shapes are maximally distinct (e.g., circles, triangles, crosses rather than subtle variations of polygons).
- **Comprehensive approach:** Recode the categories using a perceptually distinct color palette instead of, or in addition to, shape. Use a tool like ColorBrewer to select a qualitative palette. For accessibility, pair this with a distinct shape for each color.
```

```md
## Guidance

For aggregate comparison tasks in multiclass scatterplots, do not assume that using a redundant encoding (e.g., assigning both a unique color and a unique shape to a category) will improve viewer accuracy or speed compared to using a single strong encoding like color.

## Why

The cognitive process for this task involves first selecting a group of items based on a feature (e.g., "all the purple dots") and then computing an aggregate property (their average position). While redundant cues might make the selection step slightly easier, the overall task performance is limited by the more difficult aggregation step. The study found that viewers can efficiently select groups using just one strong cue (like color), so adding a second cue doesn't provide a meaningful benefit for this specific task.

## When it applies

- When the primary task for the viewer is to judge aggregate properties (like mean, trend, or clustering) of different classes within a scatterplot.
- When considering adding a second visual variable (like shape) to reinforce a primary categorical variable (like color).

## Exceptions

- **Accessibility:** Redundant encoding is a crucial strategy for accessibility. A user with color vision deficiency can rely on shape, while others can rely on color. The guideline is about performance for non-impaired users, not about the utility for accessibility. Always use redundant encodings if accessibility is a concern.
- **Lookup Tasks:** If the task involves finding a specific item or a small number of items (lookup), redundant cues can be beneficial by making targets more uniquely identifiable. This guideline is specific to aggregate judgment tasks.

## Trade-offs

- **Simplicity vs. Accessibility:** Using a single encoding creates a cleaner, less cluttered visualization. However, it is not robust for users with visual impairments related to that encoding (e.g., colorblindness). Using redundant encoding adds some visual complexity but ensures the chart is accessible to a wider audience.

## Signs of Trouble

- **Over-clutter:** The chart contains many different shapes and colors, making it visually busy without a clear performance benefit for the intended aggregate task.
- **Misplaced Effort:** Design time is spent choosing a secondary redundant encoding with the expectation it will improve performance, when that effort could be spent on other aspects of the design (like improving titles or annotations).

## How to Improve

- **For Performance:** If your goal is purely to optimize performance for the general population on an aggregate task, you can simplify the design to use a single, strong categorical encoding like color.
- **For Accessibility (Recommended):** Use redundant encodings. Pair a distinct color palette with a distinct set of shapes. This ensures the visualization is robust for all users, even if it doesn't provide an extra performance boost for some.
```

```md
## Guidance

When designing multiclass scatterplots for aggregate comparison, feel confident encoding a second, unrelated data dimension using a different visual channel (e.g., using shape for one variable when color encodes the primary comparison variable). Viewers can effectively ignore the irrelevant information.

## Why

The human visual system is adept at selective attention. When asked to perform a task based on one visual channel (e.g., "compare the average of the purple and orange dots"), viewers can effectively filter out and ignore information from another, irrelevant channel (e.g., the fact that the dots are also circles and triangles). For this task, the irrelevant cue does not create significant interference.

## When it applies

- When you need to display multiple data dimensions on a single scatterplot.
- For example, showing product categories by `color` while also showing their manufacturing plant by `shape`. A viewer can still effectively compare the average sales of two product categories.

## Exceptions

- **High Visual Complexity:** The study found that while one conflicting cue or one set of distractor points was manageable, combining *multiple* sources of distraction (e.g., a conflicting cue *and* extra distractor classes) did begin to degrade performance.
- **Salience Mismatch:** If the irrelevant (conflicting) cue is far more salient than the primary cue (e.g., using faint colors for the primary task but large, bold shapes for the irrelevant data), it may cause interference.

## Trade-offs

- **Data Density vs. Clarity:** Layering information increases the data density of the chart, allowing for more complex stories. However, it also increases visual clutter, which can be overwhelming if not managed carefully.

## Signs of Trouble

- **Visual Clutter:** The chart is so dense with different colors, shapes, and sizes that it becomes difficult to focus on any single attribute.
- **Distraction:** The secondary, irrelevant encoding is so visually prominent that it distracts from the primary task.

## How to Improve

- **Establish Visual Hierarchy:** Use a strong, salient encoding (like a bold color palette) for the primary dimension of interest. Use a more subtle encoding (e.g., less-saturated colors, or simple shape variations) for secondary, contextual dimensions. This guides the viewer's attention.
```

```md
## Guidance

In a multiclass scatterplot, you can include additional categories for context without worrying that they will interfere with a viewer's ability to compare the aggregate properties (like the mean) of two specific target categories.

## Why

Viewers can use selective attention to isolate only the categories relevant to their task. When asked to compare the "purple" and "orange" groups, they can effectively ignore the "green" (distractor) group, provided the categories are all perceptually distinct.

## When it applies

- When you want to show several categories in a scatterplot but the primary goal is to encourage comparison between a specific pair or subset of those categories.
- For example, showing your company's performance against two main competitors, while also including several smaller competitors for broader market context.

## Exceptions

- **Low Discriminability:** If the distractor classes are too similar in color (or other encoding) to the target classes, viewers may struggle to separate them, and performance will degrade.
- **Overwhelming Numbers:** The study tested a limited number of distractor classes. If the number of distractors becomes so large that it creates overwhelming visual clutter or makes the target classes difficult to locate, this principle will no longer hold.

## Trade-offs

- **Context vs. Focus:** Including more categories provides richer context but can also make the chart appear more complex. A simpler chart with only the two target categories would be more focused but provide less context.

## Signs of Trouble

- **Category Confusion:** The colors (or other encodings) are too similar, and viewers cannot easily distinguish the target classes from the distractor classes.
- **"Where's Waldo?":** The target classes are lost in a sea of other points, making them difficult to find in the first place.

## How to Improve

- **De-emphasize Distractors:** If you are concerned about interference, visually de-emphasize the distractor classes. For example, render them in a neutral color like gray or with lower opacity, while the target classes are shown in saturated colors.
- **Use Small Multiples:** For a large number of categories, consider breaking the chart into a grid of small multiples, one for each category. This completely eliminates interference but makes direct, overlaid comparison impossible.
```

```md
## Guidance

When creating a scatterplot for viewers to compare the average value of different groups, do not sample or remove data points with the assumption that it will make the task easier. The human visual system is robust to a high number of points for this type of aggregate task.

## Why

The visual system can compute aggregate statistics like mean position "preattentively" over large collections of objects. Performance for this task does not depend on serially inspecting each point. In fact, having more data points may provide a more stable and reliable visual signal of the group's central tendency, leading to slightly better performance.

## When it applies

- When the primary task is judging an aggregate property of a group of points, such as its average value, center, or spread.
- When you are considering down-sampling a large dataset to create a "cleaner" or "simpler" scatterplot.

## Exceptions

- **Overplotting:** This principle holds as long as the points are generally distinct. If increasing the number of points leads to severe overplotting where individual marks are no longer visible and merge into solid blobs, performance will degrade. In such cases, techniques like changing opacity (alpha-blending) or using density plots are required.
- **Individual Point Lookup:** If the task requires viewers to find and inspect individual data points, then a high number of points will increase search time and make the task more difficult. This guideline is specific to aggregate tasks.

## Trade-offs

- **Perceptual Accuracy vs. Technical Performance:** While showing all the data may be best for perceptual accuracy, it can lead to slow rendering times in interactive systems or large file sizes for static charts. Down-sampling may be a necessary technical compromise, but it is not a perceptual benefit for this task.

## Signs of Trouble

- **Solid Blobs:** The points are so dense that they are no longer distinguishable, forming solid shapes. This is a sign of severe overplotting.
- **Slow Rendering:** The chart takes a long time to load or respond to interaction due to the large number of points being rendered.

## How to Improve

- **Manage Overplotting:** If points are too dense, instead of removing them, use alpha-blending (reduced opacity) so that denser areas appear darker. This preserves the sense of distribution while mitigating overplotting.
- **Use Density Plots:** For very large datasets, switch from a scatterplot to a 2D density plot (e.g., a contour plot or 2D histogram / heatmap) which is designed to show the distribution of a large number of points.
```
