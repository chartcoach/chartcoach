## Guidance

When using an algorithm to optimize a color palette that has existing semantic meaning (e.g., brand colors, established conventions, or metaphors), constrain the **hue** of each color and allow the optimization to primarily adjust **lightness** and **saturation**.

## Why

The hue of a color (e.g., 'red', 'blue', 'green') carries its primary semantic identity and emotional association. Allowing an optimization algorithm to freely change hue can result in "color swaps" or shifts that break the intended meaning and confuse viewers (e.g., changing a "danger red" to an "orange"). Constraining the hue preserves this core meaning while still allowing for significant improvements in perceptual distance, as lightness and saturation can be adjusted to make the colors more distinct.

### Core Principle

Separate a color's semantic identity (primarily carried by hue) from its perceptual discriminability (which can be modified via lightness and saturation).

## When it applies

- **Branded charts:** When you must use a brand's color palette but need to make it more effective and accessible for data visualization.
- **Conventional palettes:** When using colors with strong, established conventions, such as red for "loss/decline" and green for "profit/growth," or blue/red for political parties.
- **Metaphoric palettes:** When colors have been intentionally chosen to evoke a metaphor, as in the seismology example where colors were linked to geographical regions (e.g., "California" -> Cherry/Crimson).

## Exceptions

- **Flawed source palette:** If the original semantic palette is fundamentally flawed (e.g., it uses two nearly identical hues for different categories), a change in hue for one of the categories may be necessary to achieve any meaningful separation.
- **No semantic meaning:** This guidance does not apply if you are generating a new palette from scratch with no pre-existing color associations.

## Trade-offs

- **Limited optimization:** Constraining the hue limits the total possible optimization space. An unconstrained optimization could achieve a technically higher perceptual distance, but at the cost of breaking the palette's meaning. This approach prioritizes semantic integrity over maximal mathematical optimization.

## Signs of Trouble

- **Lost in Translation:** After "improving" your brand palette, the primary brand color is no longer recognizable (e.g., your "Coke Red" has turned into a magenta).
- **Metaphor Mismatch:** An optimized palette for financial data turns the "loss" category from red to pink, weakening the established convention.
- **Color Swap:** An optimization algorithm "improves" your palette by swapping the roles of two colors (e.g., blue becomes green and green becomes blue), as seen in the paper's Fig 5(b).

## How to Improve

- **Minimal Approach: Manual Hue Lock:** When manually adjusting a semantic palette, consciously decide to "lock" the hue and only experiment with changing the lightness and saturation of the colors.

- **Comprehensive Approach: Automated Hue Constraint:** Use an optimization tool that allows for per-channel constraints (like Colourmap Hospital). For each color in your palette:
    1. Import the original color.
    2. Set a tight constraint range for the **Hue** channel (e.g., ±5-10%).
    3. Allow a wider, more flexible range for the **Saturation** and **Lightness** channels.
    4. Run the optimization. The tool will find the most discriminable version of your palette that still respects the original color identities.
