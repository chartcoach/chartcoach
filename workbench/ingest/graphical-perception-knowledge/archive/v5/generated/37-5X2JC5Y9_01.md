## Guidance

For aggregate comparison tasks in multiclass scatterplots, do not assume that using a redundant encoding (e.g., assigning both a unique color and a unique shape to a category) will improve viewer accuracy or speed compared to using a single strong encoding like color.

## Why

The cognitive process for this task involves first selecting a group of items based on a feature (e.g., "all the purple dots") and then computing an aggregate property (their average position). While redundant cues might make the selection step slightly easier, the overall task performance is limited by the more difficult aggregation step. The study found that viewers can efficiently select groups using just one strong cue (like color), so adding a second cue doesn't provide a meaningful benefit for this specific task.

## When it applies

- When the primary task for the viewer is to judge aggregate properties (like mean, trend, or clustering) of different classes within a scatterplot.
- When considering adding a second visual variable (like shape) to reinforce a primary categorical variable (like color).

## Exceptions

- **Accessibility:** Redundant encoding is a crucial strategy for accessibility. A user with color vision deficiency can rely on shape, while others can rely on color. The guideline is about performance for non-impaired users, not about the utility for accessibility. Always use redundant encodings if accessibility is a concern.
- **Lookup Tasks:** If the task involves finding a specific item or a small number of items (lookup), redundant cues can be beneficial by making targets more uniquely identifiable. This guideline is specific to aggregate judgment tasks.

## Trade-offs

- **Simplicity vs. Accessibility:** Using a single encoding creates a cleaner, less cluttered visualization. However, it is not robust for users with visual impairments related to that encoding (e.g., colorblindness). Using redundant encoding adds some visual complexity but ensures the chart is accessible to a wider audience.

## Signs of Trouble

- **Over-clutter:** The chart contains many different shapes and colors, making it visually busy without a clear performance benefit for the intended aggregate task.
- **Misplaced Effort:** Design time is spent choosing a secondary redundant encoding with the expectation it will improve performance, when that effort could be spent on other aspects of the design (like improving titles or annotations).

## How to Improve

- **For Performance:** If your goal is purely to optimize performance for the general population on an aggregate task, you can simplify the design to use a single, strong categorical encoding like color.
- **For Accessibility (Recommended):** Use redundant encodings. Pair a distinct color palette with a distinct set of shapes. This ensures the visualization is robust for all users, even if it doesn't provide an extra performance boost for some.
