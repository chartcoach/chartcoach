## Guidance

When creating multiclass scatterplots where viewers need to compare aggregate properties like the average value of different groups, encode the categories using color (hue) rather than shape.

## Why

Color is a more salient and pre-attentive visual feature than shape. This allows the human visual system to select and group items belonging to a specific category more quickly and efficiently, which is a prerequisite for performing the subsequent (and more difficult) task of judging the group's average position. Using a weaker cue like shape leads to lower accuracy.

### Core Principle

Visual channels are not created equal; some are perceptually "stronger" than others for certain tasks. For categorical grouping and selection, color is more potent than shape.

## When it applies

- When creating a multiclass scatterplot.
- When a primary task is for viewers to compare aggregate statistics (e.g., "Which group is higher on average?") between two or more categories.

## Exceptions

- **Accessibility:** If the visualization must be accessible to users with color vision deficiencies, shape becomes a critical encoding channel. In this case, use distinct shapes as the primary or redundant encoding.
- **High Cardinality:** If you have too many categories for a perceptually distinct color palette (typically > 8-10), you may be forced to use shape or other channels, though with reduced effectiveness for this task.

## Trade-offs

- **Accessibility vs. Performance:** Prioritizing color for maximum perceptual performance for the general population comes at the cost of excluding users with color vision deficiency. The best practice is often to use redundant encoding (both color and shape) to serve both goals, even if it doesn't boost performance for non-impaired users.

## Signs of Trouble

- **Task Errors:** Viewers consistently make errors when asked which category has a higher or lower average value.
- **Slow Interpretation:** Viewers take a long time to answer questions about group averages, suggesting they are struggling to segment the classes.
- **Visual "Soup":** When encoded by shape, the different categories do not visually "pop" from one another and instead blend into a uniform field of marks.

## How to Improve

- **Quick approach:** If using shape, ensure the shapes are maximally distinct (e.g., circles, triangles, crosses rather than subtle variations of polygons).
- **Comprehensive approach:** Recode the categories using a perceptually distinct color palette instead of, or in addition to, shape. Use a tool like ColorBrewer to select a qualitative palette. For accessibility, pair this with a distinct shape for each color.
