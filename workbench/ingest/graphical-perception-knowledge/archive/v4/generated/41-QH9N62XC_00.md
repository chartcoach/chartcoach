## Guidance

For the most accurate and effective visual representation, use position on a common scale (as in bar charts, scatter plots, and line charts) to encode your data, regardless of whether it is quantitative, nominal, or ordinal.

## Why

The human visual system is more accurate at perceiving and comparing differences in position along a common axis than any other visual variable (like angle, length, area, or color). This principle, established by foundational research, holds true across all primary data types, making position the most robust and reliable encoding channel. Using position leads to faster and more accurate interpretation by viewers.

## When it applies
- This is a near-universal guideline that applies to almost any visualization where accurate value comparison, ranking, or lookup is a primary goal.
- It is the default, most effective choice for encoding the most important variables in your dataset.

## Exceptions
- **Showing Composition:** While bar charts (position) can show part-to-whole relationships, some designers may prefer area-based charts like treemaps or pie charts (angle/area) if the primary goal is to emphasize the "part-of-a-whole" concept and precise comparison is secondary.
- **Geographic Data:** For map-based visualizations, position is already used to encode geographic location. In these cases, other channels like color (for choropleths) or size (for proportional symbols) must be used to encode quantitative values for those locations.

## Trade-offs
- **Space:** Charts that rely on position, like bar charts or scatter plots, can require more screen or page space than more compact representations like heatmaps or glyphs.
- **Variable Limit:** A single 2D chart can only use position to encode two, or at most three, variables (X, Y, and faceting/small multiples). Other channels are required for additional variables.

## Signs of Trouble
- **Hard to Compare:** Viewers struggle to accurately rank categories or tell which value is larger. This is common when using angle (pie charts), area (bubble charts), or color saturation.
- **Misinterpretation:** Viewers consistently misjudge the magnitude of differences between data points.
- **Reliance on Labels:** The chart is unreadable without direct data labels on every element, suggesting the visual encoding itself is failing.

## How to Improve
- **Quick Fix: Add Position Guides.** If you must use a chart that doesn't use position (e.g., a pie chart), add leader lines to align labels or use annotations that make comparisons easier. This is a patch, not a fix.
- **Moderate Redesign: Switch to a Better Encoding.** Change the primary visual channel to position. For example, convert a pie chart or a bubble chart into a bar chart. This aligns all values on a common baseline, making comparisons perceptually easier and more accurate.
- **Comprehensive Redesign: Re-evaluate the Task.** Reconsider the main goal of the chart. If the task is comparison or ranking, redesign the visualization to use position on a common scale as the primary encoding channel from the start. For example, instead of a choropleth map using color, consider a bar chart of the locations, sorted by value.
