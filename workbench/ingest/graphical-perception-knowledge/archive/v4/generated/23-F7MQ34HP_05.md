## Guidance
When encoding ordinal (ordered) or quantitative data with color, use a scale that varies in saturation or brightness (e.g., light blue to dark blue). Avoid using a scale that varies in hue (e.g., a rainbow scale).

## Why
The human visual system naturally perceives variations in brightness and saturation as a representation of "more" or "less," making sequential color schemes intuitive for ordered data. In contrast, variations in hue (like red, green, blue) are perceived as indicating different categories, not a specific order. A rainbow color scale has no natural perceptual ordering, which can lead to confusion and misinterpretation of the data.

## When it applies
- When creating a choropleth map to show a quantitative value like population density or income level.
- When coloring a heatmap to show magnitudes.
- When using color to encode any quantitative or ordinal variable in a chart.

## Exceptions
- When encoding purely nominal (categorical) data where there is no inherent order, a qualitative palette using different hues is appropriate (e.g., blue for 'Category A', orange for 'Category B').
- A diverging palette (e.g., blue-white-red) can be effective for quantitative data when there is a meaningful midpoint or zero value, as it uses two different hues to represent values above and below the midpoint.

## Trade-offs
- **Gains:** Intuitive, accurate interpretation of ordered data. Improved accessibility for users with color vision deficiencies, as changes in lightness are often more robustly perceived than changes in hue.
- **Sacrifices:** May be less visually "vibrant" or "colorful" than a rainbow palette, which some audiences may find more aesthetically engaging, despite its perceptual flaws.

## Signs of Trouble
- **The Rainbow Problem:** The chart uses a spectral (rainbow) color scheme for quantitative data.
- **Order Confusion:** Viewers are unsure whether green represents a higher or lower value than yellow.
- **False Boundaries:** The abrupt changes in hue in a rainbow palette can create the illusion of sharp boundaries in the data where none exist.
- **Accessibility Failure:** When viewed with a colorblindness simulator, distinct hues (like red and green) merge into an indistinguishable color, making the chart unreadable.

## How to Improve
- **Quick Fix: Use a Pre-built Sequential Scheme.** Most modern visualization tools (like D3, Datawrapper, Tableau) offer built-in, perceptually-vetted sequential color schemes (e.g., "Blues", "Viridis"). Switch from a custom rainbow scheme to one of these.
- **Moderate Approach: Design a Single-Hue Scheme.** Create a color scale that varies only in saturation and/or brightness of a single hue. For example, start with a light gray-blue and progress to a dark, saturated blue.
- **Comprehensive Approach: Use a Perceptually Uniform Color Space.** When designing color schemes, work in a perceptually uniform color space like CIELAB, CIELUV, or HCL. This ensures that a given step-change in the data corresponds to a perceptually equal change in the color, making the scale more accurate and easier to interpret. Tools like `d3-scale-chromatic` are based on these principles.
