## Guidance

When visualizing long, ranked lists of quantitative data, consider using a wrapped bar chart as a balanced option that combines good accuracy with efficient use of space.

## Why

Wrapped bar charts provide a strong balance between perceptual accuracy and task completion time. They eliminate the need for scrolling required by long, standard bar charts, which significantly speeds up tasks. While they introduce multiple baselines, they still use length as the primary visual encoding, which is more accurate for ranking and comparison tasks than the area encoding used in alternatives like treemaps.

## When it applies

- When visualizing a sorted list with a high number of items (e.g., more than 50) that would not fit on a single screen as a standard bar chart.
- When the primary user tasks are ranking items or comparing the values of specific items.
- When it is important to present all items simultaneously without requiring user interaction like scrolling.

## Exceptions

- If maximum perceptual accuracy is the absolute priority and task completion time is not a concern, a standard scrolled bar chart may be more accurate because it maintains a single, common baseline.
- If the primary task is to estimate the overall average of the list, a Zvinca plot (dot plot) may be faster and more accurate.

## Trade-offs

- **Multiple Baselines:** By breaking the list into columns, you lose the single common baseline of a standard bar chart. This makes it more difficult to precisely compare the lengths of bars that are in different columns.
- **Reduced Resolution:** The horizontal space available for each bar is reduced compared to a full-width scrolled bar chart. This can make it harder to distinguish between items with very similar values.

## Signs of Trouble

- **Excessive Scrolling:** Users are required to scroll extensively up and down to view a long list of bars, making comparisons between distant items difficult and time-consuming.
- **Space Inefficiency:** A chart type like a treemap is being used for a ranked list, but the primary task is precise comparison, for which the treemap's area encoding is less effective.

## How to Improve

- **Quick approach:** If using a scrolled bar chart, ensure that any items being compared can be "pinned" or selected to remain visible as the user scrolls, facilitating comparison.
- **Moderate approach:** Convert a long, scrolled bar chart into a wrapped bar chart. This immediately eliminates the need for scrolling and makes the entire dataset visible.
- **Comprehensive approach:** Evaluate the primary user task. If the task is ranking or comparison, use a wrapped bar chart. If the task is estimating the average, consider a Zvinca plot instead. If the task is finding a specific item in a very large list, a treemap might be a space-efficient alternative.

## Guidance

When the primary task is to quickly and accurately estimate the average value of a large, ranked list, use a Zvinca plot (a type of dot plot).

## Why

Zvinca plots encode values using position on a common scale, which is a highly effective visual channel. For an aggregation task like estimating the average, the human visual system can quickly perceive the "center of mass" of the cluster of dots, leading to fast and accurate judgments. Using dots instead of bars reduces the total amount of ink on the page, which may also facilitate easier overall visual estimation.

## When it applies

- The main goal is to understand the overall distribution and estimate the average (mean) of a large set of quantitative values.
- The list of items is long and needs to be displayed compactly on a single screen.
- Task completion speed is a high priority.

## Exceptions

- If the primary task is to precisely compare the values of two specific items or determine the exact rank of one item. For these tasks, length-based encodings like bar charts are more accurate.
- If the dataset has many items with identical or nearly identical values, overplotting (dots drawn on top of each other) can become an issue, obscuring the true density of values.

## Trade-offs

- **Comparison Accuracy:** You sacrifice the high precision of comparing individual items that length-based charts (like bar charts) provide.
- **Familiarity:** Zvinca plots are less common than bar charts, which might require a small amount of additional cognitive effort for viewers to understand initially.

## Signs of Trouble

- **Slow Averaging:** Users are taking a long time to estimate the average value from a visualization, possibly because they are mentally trying to read and average many individual bars.
- **Inaccurate Summaries:** When asked about the overall trend or average, users' estimates are wildly inaccurate, suggesting the chart type (e.g., a treemap or packed bars) is poorly suited for the task.

## How to Improve

- **Quick approach:** If you are using a bar chart, add a reference line indicating the average value. This directly provides the summary statistic but doesn't improve the user's ability to perceive it from the chart itself.
- **Moderate approach:** Replace a chart with a complex layout (like packed bars) with a simpler Zvinca plot or dot plot. This provides a common scale and simplifies the visual information, making averaging easier.
- **Comprehensive approach:** If summary tasks are a primary goal for a dashboard or report, provide a dedicated Zvinca plot or a statistical summary chart (like a box plot) in addition to any charts meant for individual item lookup or comparison.

## Guidance

For interactive scenarios where the highest possible accuracy in comparing ranked values is the top priority, use a standard scrolled bar chart.

## Why

A standard bar chart provides two key perceptual advantages for comparison:
1.  **Common Baseline:** All bars start from the same position (zero), making their lengths directly and accurately comparable.
2.  **High Resolution:** Each bar can use the full width of the chart area, maximizing the visual resolution and making even small differences in length easier to perceive.
This combination leads to the most accurate judgments of value, at the cost of interaction time.

## When it applies

- The most critical user task is to make precise comparisons between values or determine the exact rank of items in a long list.
- The visualization is interactive, allowing for scrolling.
- Accuracy is more important than the speed at which users can complete tasks.

## Exceptions

- When task completion time is a critical factor. The need to scroll makes this one of the slowest options.
- When the visualization must be static (e.g., for print or a non-interactive report) and the list is too long to fit on one page. In this case, a wrapped bar chart is a better alternative.
- For users with motor control impairments, the requirement to scroll can present a significant accessibility barrier.

## Trade-offs

- **Speed and Effort:** You achieve the highest accuracy at the cost of significantly longer task completion times and increased user effort (scrolling).
- **Global Context:** It is impossible to see the entire list at once, making it difficult to get a sense of the overall distribution without scrolling through the whole dataset.

## Signs of Trouble

- **User Frustration:** Users complain that it takes too long to find information or compare items that are far apart in the list.
- **Task Abandonment:** In time-sensitive scenarios, users may give up on tasks that require extensive scrolling.
- **Accessibility Issues:** Users with motor control difficulties are unable to effectively navigate the list.

## How to Improve

- **Quick approach:** Implement an interaction where users can "select" or "pin" an item to keep it visible while they scroll to another item for comparison.
- **Moderate approach:** If speed is also a concern, switch to a wrapped bar chart. This sacrifices some accuracy (due to multiple baselines and lower resolution) but dramatically improves task time by eliminating scrolling.
- **Comprehensive approach:** Provide both a scrolled bar chart for detailed, accurate lookups and a more compact summary chart (like a Zvinca plot or histogram) to show the overall distribution.

## Guidance

While length-based charts are generally superior for comparison, treemaps can be a surprisingly effective choice for visualizing large, non-hierarchical ranked lists, especially when space is limited.

## Why

Conventional wisdom holds that area-based judgments are perceptually less accurate than length-based judgments on a common scale. However, this study suggests that for treemaps, this disadvantage may not be as severe as presumed. A potential reason is that modern squarified treemap layouts are deterministic and organize rectangles by size, meaning an item's position provides a secondary (and strong) perceptual cue to its rank, which may aid interpretation. Their primary advantage is their exceptional space efficiency.

## When it applies

- You need to visualize a very large ranked list (e.g., hundreds of items) in a compact, static space.
- The task is to get a general sense of the distribution, identify the top items, and make approximate comparisons, rather than precise ones.
- The data is a flat list (non-hierarchical), which is a common but technically "off-label" use for treemaps.

## Exceptions

- When the primary task requires high-precision comparisons of value. A bar chart (scrolled or wrapped) will always be more accurate.
- When the primary task is to estimate the average value of the list. Treemaps performed poorly for this task.
- When the audience is completely unfamiliar with treemaps, as the layout can be unintuitive at first glance.

## Trade-offs

- **Accuracy for Space:** You trade the high perceptual accuracy of a bar chart for the superior space-efficiency of a treemap.
- **Comparison Difficulty:** Comparing the areas of two non-adjacent rectangles, especially those with different aspect ratios, is perceptually challenging.

## Signs of Trouble

- **Inaccurate Comparisons:** Users are making significant errors when asked to compare the values of two items, especially if the items are of similar size.
- **Misinterpretation:** Users are trying to find a hierarchical relationship in the data that does not exist, because they associate treemaps with hierarchical structures.

## How to Improve

- **Quick approach:** Add direct labels (value and category) to each rectangle in the treemap. This provides an "escape hatch" for users to read exact values instead of relying solely on area perception.
- **Moderate approach:** If precise comparisons are more important than space-efficiency, switch to a wrapped bar chart. It is more accurate and still fits in a compact space.
- **Comprehensive approach:** Use a treemap as part of a linked-view system. The treemap can serve as a dense overview and navigation tool, and selecting a rectangle can show its precise details and value in a separate panel or tooltip.

## Guidance

Avoid using packed bar charts and piled bar charts for visualizing ranked lists, as they tend to result in lower perceptual accuracy for common analysis tasks.

## Why

These chart types attempt to be space-efficient but introduce significant perceptual complexity that hinders interpretation.
- **Packed Bars:** Use a greedy layout algorithm that places bars in an unpredictable order after the first few rows. Most bars lack a common baseline, making length comparison nearly impossible.
- **Piled Bars:** Attempt to create a shared baseline by "piling" columns of bars on top of each other. This can be easily misinterpreted as a stacked bar chart, and the overlapping visual metaphor is often not intuitive, leading to errors in judgment.

Compared to simpler alternatives like wrapped bar charts or Zvinca plots, these novel layouts performed worse in accuracy for ranking, comparison, and averaging tasks.

## When it applies

- When choosing a chart type to visualize a long, ranked list of quantitative data.
- When the accuracy of user judgments is a priority.

## Exceptions

- There are no known performance-based exceptions. These chart types might be considered for their aesthetic or novel appearance in contexts where data exploration and accuracy are not the primary goals (e.g., data art), but for analytical purposes, they are not recommended.

## Trade-offs

- These charts trade perceptual clarity and accuracy for a novel, compact layout. The study suggests this is a poor trade-off, as other compact layouts (like wrapped bars) perform much better.

## Signs of Trouble

- **Viewer Confusion:** Users express confusion about how to read the chart, asking "are these bars stacked?" (for piled bars) or "what order are these in?" (for packed bars).
- **Large Errors:** User estimates of value or comparisons are significantly less accurate than with other chart types.
- **Unstable Layout:** For packed bars, small changes in the data can lead to large, unpredictable changes in the layout, breaking visual consistency.

## How to Improve

- **Quick approach:** If you must use one of these charts, add highly salient tooltips that show the exact value and rank of an item on hover to compensate for the poor perceptual qualities of the chart itself.
- **Moderate approach:** Replace a packed or piled bar chart with a wrapped bar chart. A wrapped bar chart achieves a similar space-saving goal but with a much more predictable layout and better perceptual performance for comparison and ranking tasks.
- **Comprehensive approach:** Step back and identify the primary user task. If the task is comparison, use a wrapped bar chart. If the task is estimating the average, use a Zvinca plot. These alternatives are empirically shown to be more effective.
