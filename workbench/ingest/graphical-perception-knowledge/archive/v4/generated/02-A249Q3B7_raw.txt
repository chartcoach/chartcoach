## Guidance

For tasks that require identifying the correlation between variables across many spatial locations at a single, fixed point in time, use a small multiples approach where each map represents a different time step.

## Why

This approach is significantly faster and less error-prone. Viewers only need to locate the single time step of interest and can then focus their attention on one map where all spatial information is juxtaposed. This minimizes the cognitive load of searching for and collating information that would otherwise be distributed across many complex glyphs on a single map.

## When it applies

- When the task is to assess correlation across a geographic region or all locations, but only for one specific time slice (e.g., "What was the correlation between literacy and working hours across the US in 2003?").
- When visualizing spatiotemporal data with multiple locations and multiple time steps.
- When task performance (speed and accuracy) is a higher priority than saving screen space.

## Exceptions

- If the primary task is to analyze temporal trends *at a single location*, this approach is less effective as the temporal data is scattered across different charts. In that case, a single map with a time-series glyph at each location is more appropriate.

## Trade-offs

- This approach uses more screen space than a single-map design.
- It is less effective for identifying long-term temporal trends, as viewers must scan their eyes across multiple separate charts to synthesize a trend.

## Signs of Trouble

- **Slow Performance:** Users take a long time to answer questions about a single time point because they have to visually scan across many glyphs on a single map to find the correct time step for each location.
- **High Error Rate:** Users make frequent mistakes when identifying spatial patterns for a single time step.
- **User Complaints:** Users report that "it's hard to make analyses for one time step" when using a single map with time-series glyphs.

## How to Improve

- **Quick Fix: Highlight the Time Step.** If you must use a single map with time-series glyphs, add interaction to highlight the relevant time step across all glyphs (e.g., on hover). This reduces the search burden but doesn't fix the core layout mismatch.
- **Comprehensive Redesign: Switch to Small Multiples.** Redesign the visualization to use small multiples, where each small chart represents a single time step. This directly juxtaposes the spatial information for the time point of interest, aligning the visual layout with the primary task.

## Guidance

When the primary task is to identify correlation and trends over a long period (i.e., all available time steps), use a single map that encodes the entire time series within a glyph at each location (e.g., a miniature bar chart or sparkline).

## Why

This design is faster and less error-prone for long-term trend analysis. It juxtaposes all temporal information for each location, making it easy to see trends like correlation and monotonic evolution over time with a single glance at a glyph. This reduces the cognitive load of having to scan and integrate information from multiple separate maps.

## When it applies

- When the task is to characterize the correlation and its evolution over the entire duration of the dataset (e.g., "For each state, what was the correlation trend between 2000 and 2009?").
- This holds true whether the spatial scope is a single location, a region, or all locations.

## Exceptions

- If the primary task is to compare spatial patterns at a *single point in time*, this approach is much slower and more error-prone than using small multiples.

## Trade-offs

- This design makes it harder to compare the state of all locations at a single moment in time, as that information is "buried" within each time-series glyph.
- The complexity of the glyphs can increase with the number of time steps, potentially leading to visual clutter.

## Signs of Trouble

- **Slow Performance:** Users are slow to identify long-term trends because they have to scan back and forth between many small multiple maps.
- **Memory Errors:** Users struggle to remember patterns from one map to the next, making it difficult to synthesize a temporal trend.
- **Visual Fragmentation:** The temporal story is broken up across many small, separate views, preventing a holistic understanding of trends.
- **User Complaints:** Viewers comment that it's difficult to "observe evolution over time" with small multiples.

## How to Improve

- **Quick Fix: Add a "Sparkline" Overview.** If using small multiples, provide a small sparkline or summary glyph next to each location's label that summarizes its trend, offering a temporal overview.
- **Comprehensive Redesign: Switch to a Single Map with Time-Series Glyphs.** Redesign the visualization to use a single base map. At each location, place a glyph (like a miniature bar chart or line chart) that encodes the entire time series for that location. This directly juxtaposes the temporal information, aligning with the trend-finding task.

## Guidance

When analyzing correlations over a *time interval* (not a single point or all time), the optimal visualization strategy depends on the spatial scope. There is a trade-off between juxtaposing space (small multiples) and juxtaposing time (single map with glyphs).

## Why

The most efficient design is the one that minimizes the amount of information a user needs to visually scan and collate. If the task involves few locations, it's better to group time data together. If it involves many locations, it's better to group spatial data together.

## When it applies

- When the task involves analyzing a subset of time steps and a subset of locations (e.g., "What was the correlation in the West from 2003-2006?").
- **For a few spatial locations:** Use a single map with time-series glyphs. The user only needs to check a few glyphs, and the relevant time interval is easy to find within each.
- **For many spatial locations:** Use small multiples. The user has to check multiple maps (but only a subset of them), and identifying the many locations on each is easier than checking many complex glyphs.

## Exceptions

- The study found inconclusive results for tasks involving a medium number of locations (a "region"). The performance trade-off is balanced, and no single technique was clearly superior. In this "middle ground," other factors like user preference or familiarity may be more important.

## Trade-offs

- A static visualization cannot easily adapt to a user's changing analytical focus. An optimal layout for analyzing a few locations will be inefficient for analyzing many, and vice versa.
- Implementing an adaptive interface that switches layouts based on user interaction requires more development effort.

## Signs of Trouble

- **Task-Layout Mismatch:** A user is analyzing a single state's trend over a few years but has to scan across multiple small-multiple maps to do so.
- **Inverse Mismatch:** A user is analyzing a pattern across the entire country for a few years but has to decode dozens of complex bar-chart glyphs on a single map.
- **User Frustration:** Users express that the information they need is "scattered all over the place."

## How to Improve

- **Minimal Approach: Add Guidance.** Instruct users on the most efficient way to read the current chart for their task (e.g., "To see the trend for Texas, focus only on its bar chart and ignore other states").
- **Moderate Approach: Offer Both Views.** In an interactive setting, provide a toggle that allows users to switch between a small multiples view (juxtaposing space) and a single-map glyph view (juxtaposing time).
- **Comprehensive Approach: Use an Adaptive Visualization.** Build an interactive system that detects the user's focus (e.g., through selection or filtering). If the user filters to a few locations, the system could automatically switch to a single-map glyph view. If they filter to a few time steps, it could switch to a small multiples view.

## Guidance

When using small multiples to compare spatial patterns across time, favor techniques that maintain a consistent, stable base map geography, such as proportional symbol maps. Avoid techniques like Dorling cartograms where the geography (e.g., size and position of states) changes in each map.

## Why

A stable geography makes it easier for viewers to re-identify and match locations from one map to the next. When the map features themselves shift, it adds cognitive load and increases the risk of error, as the viewer must reorient themselves with each new map. The study found that proportional symbol maps (where symbols are overlaid on a static map) were less error-prone than Dorling cartograms for this reason.

## When it applies

- When creating small multiple maps for comparison across time.
- Especially relevant for simpler tasks, such as comparing patterns at a single point in time, where the cognitive cost of re-identifying locations is high relative to the simplicity of the task.

## Exceptions

- If the primary goal is to emphasize the magnitude of a variable that is encoded by the geographic distortion (the core purpose of a cartogram) and comparison across maps is a secondary goal.
- The performance difference was less pronounced for more complex tasks (analyzing time intervals or all time), suggesting the cost of re-identification is a smaller part of the overall cognitive effort in those cases.

## Trade-offs

- Proportional symbol maps can suffer from symbol occlusion, especially in dense areas, a problem that Dorling cartograms are designed to mitigate by displacing features.
- Cartograms can be more effective at correcting for perceptual biases where geographically larger areas are given more visual weight regardless of their data value. Using a standard map with symbols does not address this bias.

## Signs of Trouble

- **Location Matching Errors:** Users struggle to find the same state or region across different maps in the small multiple set.
- **User Complaints:** Viewers mention "difficulty matching a location" or that the "positions of locations shifted" across maps.
- **Slow Comparison:** Comparisons between maps are slow because users have to spend time re-learning the layout of each map.

## How to Improve

- **Quick Fix: Add Persistent Labels.** If you must use changing cartograms, ensure every geographic feature has a clear, persistent label to aid re-identification. This doesn't fix the shifting layout but provides a necessary crutch.
- **Moderate Redesign: Use Linked Highlighting.** In an interactive setting, implement linked highlighting where hovering over a location in one map highlights it in all other maps.
- **Comprehensive Redesign: Switch to Proportional Symbols on a Static Map.** Change the design from a cartogram to a proportional symbol map. This uses a stable base map and overlays symbols (like circles) whose size or color encodes the data, ensuring a consistent spatial layout in every multiple.
